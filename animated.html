Make animated explainer videos with Claude

A step-by-step SOP for turning a topic and a style screenshot into a finished vertical MP4, using Claude Code or the Claude web app.

  • About 15 minutes to set up, once
  • Beginner
  • Last updated October 28, 2026

Quick answer

To make an animated explainer with Claude, give it a topic and a style screenshot, approve the script, storyboard and style frame, then let it build the scenes, add sound, render and check the video. Claude Code renders on your computer with Remotion. The Claude web app renders in its own workspace and returns an MP4, a GIF and a project zip, at higher token use.

Overview

Purpose

This SOP gets you from a topic and a style screenshot to a finished vertical MP4 explainer, without opening any animation software.

You approve the script, the storyboard and one style frame. Claude researches, writes, builds the scenes in code, adds sound, renders the file and checks its own frames for mistakes.

Who this is for

  • Founders and small teams who want short explainer videos without hiring a motion designer
  • Anyone who can describe a look and a message but has never used After Effects
  • Team members handed this process who need to run it from scratch

How it works: the 8 stages

Every video goes through the same stages, in this order. You only step in at stages 2, 3 and 4.

  1. ResearchClaude pulls 3 to 5 facts worth saying.
  2. ScriptA 45 second voiceover with a hook in the first sentence. You approve.
  3. StoryboardThe script split into timed scenes. You approve.
  4. Style lockColours, fonts and motion feel from your screenshot, shown as one still frame. You approve.
  5. BuildEach scene built as code.
  6. SoundMusic and effects synced to the motion.
  7. RenderA 1080 by 1920 MP4.
  8. QA and fixClaude checks frames and fixes what it finds.

The tool underneath is Remotion, a free library that turns code into video. Claude Code uses it directly, and the Claude web app uses it when it installs in the workspace. You never write the code. Claude does.

Path A: Claude Code

Follow steps 1 to 5. Everything runs on your computer and Claude hands you a finished MP4.

Path A

01

Check your tools

Four things, all free except Claude. Setup takes about 15 minutes, once.

  1. Install Claude Code and log in. Claude Codeclaude.com/claude-code
  2. Install the LTS version of Node.js, then type node -v in your terminal to confirm it shows version 18 or newer. Node.jsnodejs.org
  3. Install FFmpeg, then type ffmpeg -version to confirm it works.
    bash
    # Mac
brew install ffmpeg

# Windows
winget install ffmpeg
  4. Create one empty folder on your computer called animation-studio.
  5. Take a screenshot of any reel, ad or explainer whose look you love. This is your style reference.
Optional

Download a folder of royalty free sound effects (whoosh, pop, click, riser) and one music track. Pixabay and Uppbeat have free ones. If you skip this, Claude generates simple effects in code.

Tick each item when it is done:

  • Claude Code installed and logged in
  • Node.js installed (node -v works)
  • FFmpeg installed (ffmpeg -version works)
  • Empty animation-studio folder created
  • Style screenshot saved

Path A

02

Set up the studio (once)

You only do this the first time. Every video after it reuses the same folder.

  1. Open your terminal and go into the animation-studio folder.
  2. Type claude and press Enter.
  3. Paste this prompt:
    Prompt
    Set up a Remotion video studio in this folder for vertical explainer videos.

1. Create a new Remotion project with the blank TypeScript template. Use npm.
2. Set the default composition to 1080 x 1920, 30 fps.
3. Create these folders:
   - /videos (one subfolder per video, holds script, storyboard and scenes)
   - /public/sfx (sound effects)
   - /public/music (background tracks)
   - /public/styles (style screenshots I give you)
   - /out (rendered MP4s)
   - /qa (still frames pulled for checking)
4. Install @remotion/google-fonts, @remotion/transitions and @remotion/media-utils.
5. Build a small reusable component library in /src/lib:
   - KineticText (words animate in one by one with spring easing)
   - Counter (a number that counts up)
   - IconPop (an icon or emoji that scales in with overshoot)
   - BarReveal (a bar or progress line that grows)
   - SceneWrapper (handles background, safe margins and the transition in and out)
6. Create a file called CLAUDE.md in the root that says:
   "Before any video work, read ANIMATION_PLAYBOOK.md and follow it exactly."
7. Run the Remotion studio once to confirm it opens, then render a 3 second test
   clip to /out/test.mp4 to prove rendering works.

Tell me when the test clip is rendered and where it is.
  4. Wait for Claude to report that the test clip is rendered. Open /out/test.mp4 to confirm it plays.

When the test clip works, your studio is ready.

Path A

03

Save the playbook file

This is the file that does the heavy lifting. Claude reads it before every video because of the CLAUDE.md file you created in step 2.

  1. Copy everything in the box below.
  2. Save it as ANIMATION_PLAYBOOK.md in the root of your animation-studio folder.
  3. Edit the "My defaults" section at the top to match your brand. Leave the rest as is.
Markdown
# ANIMATION PLAYBOOK

You are the motion designer, scriptwriter and editor for this studio.
Follow every phase below in order. Never skip a phase. Never build before the
script and storyboard are approved.

## My defaults (edit these)
- Format: 1080 x 1920, 30 fps, vertical
- Default length: 45 seconds
- Audience: small business owners who are not technical
- Tone: plain, confident, one person talking to one person
- Brand colours: [primary hex], [accent hex], [background hex]
- Fonts: [headline font], [body font] (Google Fonts only)
- Banned: jargon, filler words, more than 7 words on screen at once

## PHASE 1: RESEARCH
1. Research the topic. Use web search if available.
2. Write /videos/[slug]/research.md with:
   - 3 to 5 facts, stats or steps worth saying (with source links)
   - The one idea the viewer must walk away with
   - 3 common misunderstandings about the topic
3. Do not move on until research.md exists.

## PHASE 2: SCRIPT
1. Write /videos/[slug]/script.md.
2. Rules:
   - 110 to 125 words for 45 seconds (about 2.6 words per second)
   - Hook in the first sentence. Under 10 words. Makes a claim or opens a gap.
   - One idea per sentence. Short sentences.
   - End with one clear takeaway or call to action.
   - Read it out loud in your head. If a line sounds written, rewrite it.
3. Give 3 hook options at the top of the file.
4. STOP. Show me the script and the 3 hooks. Wait for my approval.

## PHASE 3: STORYBOARD
1. Write /videos/[slug]/storyboard.md as a table with these columns:
   Scene # | Start-End (sec) | Voiceover line | On-screen text | Visual | Motion | SFX
2. Rules:
   - A new scene or visual change every 2 to 4 seconds. Nothing static longer than 4s.
   - On-screen text max 7 words. Never the full voiceover.
   - Every number gets a Counter. Every list gets a staggered reveal.
   - Scene 1 must move within the first 0.3 seconds.
   - Keep all text inside safe zones: 120px from top, 320px from bottom,
     80px from sides (platform UI covers the rest).
3. STOP. Show me the storyboard. Wait for my approval.

## PHASE 4: STYLE LOCK
1. Study the screenshot in /public/styles.
2. Write /videos/[slug]/style.md with:
   - Background (colour, gradient, texture, grid)
   - Exact hex colours you see (max 5)
   - Closest Google Fonts for headlines and body, plus weights and sizes
   - Shapes and containers (cards, pills, outlines, radius)
   - Motion personality: snappy, smooth, bouncy or minimal
   - Easing: spring config (damping, stiffness) that matches that personality
3. Build ONE still style frame (scene 1 at its most complete moment) and
   render it as a PNG to /qa/style-frame.png.
4. STOP. Show me the style frame next to the screenshot. Wait for approval.

## PHASE 5: BUILD
1. One React component per scene in /videos/[slug]/scenes/.
2. One master composition that sequences them with <Series> or <Sequence>.
3. Rules:
   - Use the /src/lib components before writing new ones.
   - All timing in frames (30 frames = 1 second). No hard-coded milliseconds.
   - Use spring() and interpolate() for every movement. No linear motion except
     progress bars.
   - Stagger related elements by 3 to 5 frames.
   - Every scene has an exit. Nothing just disappears.
   - Colours and fonts come only from style.md.
4. Open the Remotion studio preview and scrub through to confirm it plays.

## PHASE 6: SOUND
1. Add a background music track at low volume (0.15 to 0.25).
2. Add a sound effect on every major motion beat: text slam, icon pop,
   transition, counter finish. Use files in /public/sfx.
3. Sync each SFX to the exact frame the motion peaks, not when it starts.
4. Duck the music to 0.08 under any voiceover file if one exists.
5. Fade music in over the first 10 frames and out over the last 30.

## PHASE 7: RENDER
1. Render to /out/[slug].mp4 with codec h264, CRF 18.
2. Confirm duration matches the storyboard within 0.5 seconds.

## PHASE 8: QA AND FIX (do not skip)
1. Use FFmpeg to pull one frame every second into /qa/[slug]/.
2. Open and look at every frame. Check each against this list:
   - Any text cut off, overlapping or outside safe zones?
   - Any text too small to read on a phone (under 48px)?
   - Any frame with nothing moving or looking empty?
   - Any colour or font not from style.md?
   - Spelling correct on every word?
   - Does on-screen text match the storyboard?
   - Is the hook readable in the first 2 seconds?
3. Write /videos/[slug]/qa-report.md listing every issue with its frame number.
4. Fix every issue, re-render, re-pull frames and check again.
5. Repeat until the QA report has zero issues. Maximum 3 rounds.
6. Tell me: final file path, duration, and what you fixed.

Path A

05

Render, check and fix

After you lock the style, Claude builds, adds sound, renders and runs its own QA loop. You get a final MP4 in /out and a QA report listing what it fixed.

  1. Open the MP4 on your phone, not your laptop. That is where your audience sees it.
  2. If you want a second QA pass, paste:
    Prompt
    Run Phase 8 again with fresh eyes. Pull a frame every 0.5 seconds this time.
Be strict. Assume there are at least 3 problems and find them.
  3. If something specific is off, paste:
    Prompt
    At [timestamp], [describe what's wrong]. Fix it, re-render, and show me the
frame at that timestamp before and after.
  4. To make a new video in the same style, paste:
    Prompt
    New video, same style as /videos/[previous-slug]/style.md.
Topic: [NEW TOPIC]. Skip Phase 4 and reuse the locked style.
Start from Phase 1.
  5. To make a different length, paste:
    Prompt
    Make a 15 second cut of /videos/[slug]. Keep the hook and the takeaway.
Cut everything in the middle down to the 2 strongest beats.
Re-run Phases 6 to 8.

Path B: Claude web app

No installs. Claude builds and renders the animation inside its own workspace, checks the frames itself, and hands you a finished MP4, a GIF and a zipped project folder to download from the chat.

Same 8 stages as Path A. The only real cost is higher token use, because every script, scene file and render happens inside the conversation.

Path B

01

Create your studio Project (once)

  1. Go to claude.ai, click Projects, then Create Project. Claudeclaude.ai
  2. Name it Animation Studio.
  3. Open Set project instructions and paste the web playbook from step 2.
  4. Under Project knowledge, upload 1 to 3 screenshots of styles you love. Name them clearly, for example style-dark-grid.png.
  5. In Settings, turn on code execution and file creation. This is what lets Claude run code, render video and give you files.

Every chat you start inside this Project already knows the playbook.

Warning

Remotion needs to download a browser inside the workspace, and the workspace may block that. The playbook handles this with two fallback render methods. Run one short test video before you rely on this path, so you know which method your account uses.

Path B

06

Keep token use down

Web app builds cost more tokens than Claude Code because the code, the frames and the files all live in the chat. These habits cut it a lot.

  1. Approve text before motion. Fixing a script line costs almost nothing. Fixing a rendered scene costs a lot.
  2. Lock the style with one still frame. Never build the full video on an unchecked style.
  3. Test the hardest scene first. A 10 second test render catches problems early.
  4. Fix by timestamp. Say "at 0:18, the number is cut off" instead of "redo the middle".
  5. Use one chat per video. Long chats carry every earlier render with them. Start a new chat for each topic.
  6. Reuse the style. After your first video, upload its style.md to Project knowledge and say "use the locked style, skip Phase 4".
  7. Keep the playbook lean. Only edit the defaults. Extra rules in Project instructions are paid for in every chat.
  8. Build the short cut first if you are tight on usage. Longer videos cost more.

01

Approve at three checkpoints

Claude stops three times. This is where you shape the video. Pick the prompt that fits.

Checkpoint 1: the script (Phase 2)

  1. To approve, paste:
    Prompt
    Go with hook option [1/2/3]. Script approved. Move to Phase 3.
  2. To push back on the wording, paste:
    Prompt
    The script sounds written, not spoken. Rewrite it like I'm explaining this to
one friend over coffee. Cut any line that doesn't earn its place.
Keep it between 110 and 125 words.
  3. To push back on the hook, paste:
    Prompt
    The hook is too soft. Give me 5 new hooks that make a bold claim or call out a
mistake my audience is making. Under 10 words each.

Checkpoint 2: the storyboard (Phase 3)

  1. To approve, paste:
    Prompt
    Storyboard approved. Move to Phase 4.
  2. If scenes feel static, paste:
    Prompt
    Scenes [X] to [Y] feel static. Add more visual change: break the text into
smaller beats, add a counter or icon, and change the layout every 2 seconds.
  3. If there is too much text, paste:
    Prompt
    Too much text on screen. Cut every on-screen line to 5 words or fewer.
Let the motion carry the meaning.

Checkpoint 3: the style frame (Phase 4)

  1. To approve, paste:
    Prompt
    Style locked. Build it. Run Phases 5 through 8 without stopping.
  2. If it does not match your reference, paste:
    Prompt
    The style frame doesn't match the reference. Compare them side by side and list
every difference you see (colour, font weight, spacing, background, corner
radius). Fix each one and show me the new frame.
  3. If the motion feel is wrong, paste:
    Prompt
    The motion should feel [snappier / smoother / more playful]. Update the spring
settings in style.md and explain what you changed.

Frequently asked questions

Do I need to know motion design or code to make these videos?

No. You choose the topic, the style and the wording. Claude writes the code, builds the scenes, adds sound and renders the file.

Which path should I start with, Claude Code or the Claude web app?

Start with the Claude web app if you have never used a terminal. Choose Claude Code if you make several videos a week, because it costs fewer tokens per video.

Can the Claude web app produce an MP4 file?

Yes. With code execution and file creation turned on, Claude renders inside its own workspace and gives you an MP4, a GIF and a zipped project folder to download. The only real difference from Claude Code is higher token use.

Why does Claude stop and wait for approval?

Fixing a script line costs almost nothing, while fixing a rendered scene costs a lot. The playbook makes Claude stop after the script, the storyboard and the style frame.

What format and length do the videos use?

The default is a vertical 1080 by 1920 video at 30 frames per second and 45 seconds long. You can ask for a shorter cut, such as 15 seconds.

Can I reuse the same style for the next video?

Yes. Every video saves a style.md file. Point Claude at it on the next video and skip the style lock phase.

Where do the sound effects come from?

Use royalty free libraries such as Pixabay or Uppbeat, or let Claude generate simple effects in code.
