Purpose

What this does

A cheat code is a short slash command typed before your prompt. It tells Claude what mode to answer in, so you get blunter critique, stronger counterarguments, plainer language, gap analysis or bigger ideas on demand.

After this SOP you can set the codes up so Claude reads them consistently, use each one with the right inputs, chain them into repeatable workflows, troubleshoot weak output and create your own.

Who this is for

  • Founders, managers, analysts and marketers
  • Students and operators who use Claude for work
  • Anyone who wants less flattery and more useful feedback

Tools needed

  • Claude (any plan)
  • The definitions block from Step 1
  • A real draft, plan or text to test on
How cheat codes actually work
These are not built-in Claude commands. Claude reads the short label, infers your intent and adjusts its tone and structure. So results are more consistent when you define each code once, and you can edit a definition if it is too harsh, too soft or too long.

Quick reference

01

Setup · 2 minutes

Paste the definitions block

Claude has no hidden slash commands, so you define each code once. Start a new chat, or add this block to Settings > Personal preferences so it applies everywhere. Edit the wording to taste.

Definitions block

Prompt
I use shorthand commands at the start of my messages. When you see one, follow its definition:

/brutal - Give blunt, honest critique. No flattery, no softening, no filler. Tell me exactly why this is weak, ranked by severity. Do not just agree with me.

/steelman - Argue the strongest possible case against my position, as its smartest defender would. Not a devil's advocate and not a strawman. The best version of the opposing view.

/eli5 - Explain this as if I am five. Plain words, short sentences, one everyday analogy. Then tell me what actually matters for my situation.

/what am i missing? - Review what I pasted and list the gaps: assumptions I have not stated, risks I have not addressed, and questions I have not asked. Lead with the most important.

/10x this - Do not improve this by 10 percent. Show me what a version that is ten times better or bigger would look like, even if it requires a completely different approach.
02

Setup · 2 minutes

Test each code

Send one short test per code and confirm the tone and format match what you want.

Example test

Prompt
/eli5 what is an indemnity clause?
  1. Run one test for each of the five codes.
  2. Check the tone, length and structure of each answer.
  3. If a code is ignored, confirm the definitions block is in the chat or in your preferences.
03

Setup · 2 minutes

Adjust and save your version

  1. If output is too long, add max 200 words to the definition.
  2. If it is too harsh, add be direct but constructive.
  3. Save your final definitions block somewhere you can paste it again, such as a notes app.
Tip
You can edit any definition at any time. If a code is too harsh, too soft or too long, change the wording and test again.
04

Universal procedure

Use the 5-step loop for any code

  1. Prepare the input. Gather the actual draft, plan or text. Codes work far better on real material than on vague descriptions.
  2. Add context. One or two lines: who it is for, what you are trying to achieve, any constraints.
  3. Type the code first. Put it at the very start of your message, followed by the input.
  4. Read the output critically. Cheat codes produce a perspective, not a verdict. Decide what to act on.
  5. Follow up. Ask Claude to expand the strongest point, rewrite the draft, or turn the output into an action list.
05

Cheat code · /brutal

Run /brutal

What it does: Claude drops its default politeness and tells you plainly why your idea, draft or plan is weak. It aims for honest, not cruel.

Why it matters: Claude tends to be agreeable. If you ask "is this good?" you often get encouragement first. /brutal flips that so problems surface before an audience finds them.

When to use it

  • Before sending an important email, proposal or pitch
  • Before publishing an article, post or landing page
  • When you suspect friends and colleagues are being too nice
  • When reviewing your own work late in a project and you are too close to it

How to run it

  1. Paste your draft or describe your idea in full.
  2. Say who the audience is and what success looks like.
  3. Type /brutal at the start.
  4. Ask for ranked feedback so you can prioritise.
  5. Ask for a rewrite of the weakest section.

Example prompts

Pitch email

Prompt
/brutal
Here is my cold email to a VP of Operations. Goal: get a 20-minute call. Tell me why they would ignore it, ranked by severity.

[paste email]

Business idea

Prompt
/brutal
My idea: a subscription box for home coffee roasters. Target: 25-40 year olds. Tell me the three reasons this is most likely to fail.

Resume

Prompt
/brutal
Review my resume for a senior product manager role. What makes a hiring manager reject it in the first 10 seconds?

[paste resume]

Use cases

SituationWhat it gives you
Sales emailVague value proposition, buried ask, generic opening
Product conceptWeak differentiation, unclear customer, wishful pricing
Blog postPadding, weak hook, no clear takeaway
PresentationToo many ideas per slide, no story arc
Watch-outs
• Harsh does not mean correct. Verify any factual claim Claude makes.
• Claude can over-criticise when pushed. Ask "which of these would a reasonable expert actually agree with?" to filter.
• Pair it with a follow-up such as "now fix the top two problems" so the critique turns into progress.
06

Cheat code · /steelman

Run /steelman

What it does: Claude builds the strongest possible version of the opposing view. This is different from a devil's advocate, who argues for the sake of it. A steelman is the case a smart, informed opponent would genuinely make.

Why it matters: Most of us only test our ideas against weak objections. Hearing the best counterargument before a decision makes you better prepared, or changes your mind.

When to use it

  • Before a proposal, board paper or negotiation
  • Before a big decision such as a hire, acquisition, pivot or move
  • When you feel very certain, which is often when you should test hardest
  • When preparing for a debate, interview or Q&A

How to run it

  1. State your position clearly in one or two sentences.
  2. Add the key reasons you hold it.
  3. Type /steelman and name the position to attack.
  4. Ask Claude to list the opponent's best three arguments and the evidence behind each.
  5. Ask: "What would have to be true for them to be right?"
  6. Update your plan or prepare your rebuttals.

Example prompts

Strategic decision

Prompt
/steelman
I am planning to move our team fully remote and close the office. My reasons: lower costs, wider hiring pool, staff preference. Give me the strongest case against doing this.

Pricing

Prompt
/steelman
We want to raise prices 20 percent next quarter. Argue the best case that we should not, as a smart head of sales would.

Pre-meeting prep

Prompt
/steelman
I am proposing we build this feature in-house rather than buy. The CFO will oppose it. Write the CFO's best argument, then list the three questions she is most likely to ask.

Use cases

SituationWhat it gives you
Board or leadership proposalAnticipate objections and prepare responses
Hiring or firing decisionSurface risks you are discounting
Policy or strategy debateUnderstand opponents fairly
Personal choices (job, move)Stress-test emotional reasoning
Watch-outs
• A steelman is not a recommendation to change course. It is input.
• Ask for evidence and examples, then verify them. Claude can state plausible arguments that need checking.
• Do a second pass: "Now rebut each of those as strongly as you can." This shows how well your position survives.
07

Cheat code · /eli5

Run /eli5

What it does: Claude explains something in plain language, as if to a five-year-old: short sentences, everyday analogies, no jargon.

Why it matters: Legal, financial and technical text hides meaning behind specialist words. A plain-language pass tells you what you are really agreeing to or dealing with.

When to use it

  • Contracts, terms of service, leases and policies
  • Financial statements, investment products and tax letters
  • Technical documentation outside your field
  • Learning a new topic quickly
  • Preparing to explain something to a client or non-expert

How to run it

  1. Paste the exact text, not a summary of it.
  2. Type /eli5 first.
  3. Ask for the explanation plus "what this means for me" and "what I should check".
  4. Ask Claude to define any term it used that you still do not understand.
  5. For anything with legal or financial consequences, confirm with a qualified professional.

Example prompts

Contract clause

Prompt
/eli5
Explain this clause. Then tell me who it protects and what could go wrong for me.

"The Licensee shall indemnify and hold harmless the Licensor from any and all claims arising out of the Licensee's use of the Software."

Finance

Prompt
/eli5
What is the difference between a Roth IRA and a traditional IRA? Use one simple analogy, then give me a 3-line summary of which suits someone in their 30s.

Technical

Prompt
/eli5
Explain what an API is to a non-technical marketing manager. Then give two real examples from tools they already use.

Use cases

SituationWhat it gives you
Signing a vendor agreementUnderstand obligations before negotiating
Reading a loan or insurance documentSpot hidden costs and exclusions
Onboarding to a new industryBuild vocabulary fast
Writing for clientsDraft a plain-English version of a technical report
Watch-outs
• Simplifying can lose nuance. Ask: "What did you simplify that matters?"
• This is not legal or financial advice. Use it to understand, then consult a professional for decisions.
• For a stronger result, add "then explain it again at a professional level" to compare both versions.
08

Cheat code · /what am i missing?

Run /what am i missing?

What it does: Claude reviews a plan, document or idea and identifies the gaps: unstated assumptions, unaddressed risks, unanswered questions and overlooked stakeholders.

Why it matters: Reviewers usually react to what is on the page. This prompt asks Claude to look for what is not there, which is where most plans fail. The video's creator calls it the one used most.

When to use it

  • After drafting any plan, strategy, spec or project brief
  • Before kickoff, launch or sign-off
  • When something feels fine but you cannot say why you are uneasy
  • As a pre-mortem before a major commitment

How to run it

  1. Paste the full plan or document.
  2. Add context: goal, timeline, budget, audience, constraints.
  3. Type /what am i missing?
  4. Ask Claude to organise gaps into categories (risks, assumptions, dependencies, stakeholders, metrics).
  5. Ask for the top three gaps to fix first.
  6. Revise the document, then run the prompt again until the returns shrink.

Example prompts

Project plan

Prompt
/what am i missing?
Here is my launch plan for a new app feature. Goal: 5,000 activations in 60 days. Budget: $20k. Team: 3 people.

[paste plan]

Group the gaps into assumptions, risks, dependencies and measurement. List the top three to fix before kickoff.

Strategy document

Prompt
/what am i missing?
Review this 2027 strategy memo as if you were a skeptical COO. What questions would she ask that I have not answered?

Event or personal plan

Prompt
/what am i missing?
I am organising a 150-person conference in March. Here is my checklist. What have I forgotten?

Use cases

SituationWhat it gives you
Product launchNo success metric, support not staffed, unclear owner
Budget proposalMissing contingency, hidden recurring costs
Hiring planNo onboarding plan, unclear role success criteria
Project kickoffDependencies on other teams, no rollback plan
Watch-outs
• Claude only knows what you tell it. More context produces more relevant gaps.
• Not every gap is important. Ask Claude to rank by impact and likelihood.
• Do not let this become endless review. Set a rule: two passes, then decide.
09

Cheat code · /10x this

Run /10x this

What it does: Instead of polishing your idea, Claude imagines a version that is ten times better or bigger, which usually means a completely different approach rather than small improvements.

Why it matters: Asking for "better" gets you 10 percent. Asking for 10x forces new assumptions about scale, method and ambition.

When to use it

  • When a plan feels safe, incremental or boring
  • During brainstorming and strategic planning
  • When you hit a ceiling with the current approach
  • Before locking in a goal or target

How to run it

  1. Describe the current plan, goal or draft and its numbers if you have them.
  2. Type /10x this
  3. Ask Claude for three distinct 10x directions, not three variations of one.
  4. For each, ask what would have to change: resources, model, team, timeline.
  5. Pick the most interesting one and ask for a first-step test that costs little.
  6. Run the idea through /brutal and /what am i missing? to ground it.

Example prompts

Growth goal

Prompt
/10x this
Our goal is to grow the newsletter from 5,000 to 7,500 subscribers this year. Show me three completely different ways to reach 50,000 instead, and what each would require.

Content

Prompt
/10x this
My plan is one blog post per week. What would a 10x version of my content strategy look like? Give me an unconventional approach and a small test I can run next week.

Product

Prompt
/10x this
We are adding a dashboard filter to our analytics tool. What would a 10x version of this feature look like, and is the filter the wrong thing to build?

Use cases

SituationWhat it gives you
Annual goalsDifferent channels or business model rather than "work harder"
Marketing campaignPartnerships or community-led approaches instead of more ads
Product roadmapRethinking the problem rather than adding features
Personal projectsBigger scope or a more ambitious audience
Watch-outs
• 10x ideas are often unrealistic as stated. Treat them as direction, then scale back to a testable step.
• Always ask for a small experiment so ambition becomes action.
• Combine with /brutal to separate bold from unrealistic.
10

Combination workflows

Chain the codes into workflows

The codes are strongest when chained. Three tested sequences:

Workflow A: Pre-launch review

  1. /what am i missing? on your plan to find gaps.
  2. Fix the top three gaps.
  3. /brutal on the revised plan.
  4. /steelman against your main assumption.
  5. Finalise.

Workflow B: Decision memo

  1. Write your recommendation.
  2. /steelman to see the best case against it.
  3. Add rebuttals and evidence to your memo.
  4. /eli5 on the final memo to check it is clear to non-experts.

Workflow C: Ambition reset

  1. /10x this to open up possibilities.
  2. Choose one direction.
  3. /what am i missing? to expose gaps in that bold plan.
  4. /brutal to remove wishful thinking.
  5. Define a small first test.

Custom codes

Build your own cheat codes

Use this template to create codes for your own work, then add them to your definitions block.

Template

Prompt
/[name] - [What mode Claude should adopt]. [Format of the output]. [What to avoid].

Examples

Prompt
/exec - Summarise this for a busy executive in 5 bullet points and one recommended action. No background.

/redteam - Act as an adversary trying to make this plan fail. List the three most likely attack paths.

/checklist - Turn this into a step-by-step checklist with owners and deadlines blank for me to fill.

Tips for good codes:

  • Keep the name short and memorable.
  • Define the output format, not just the attitude.
  • Include what to avoid, for example "no preamble".
  • Test and refine after a few uses.

Troubleshooting

When output is weak

What you seeLikely causeFix
Claude ignores the code and answers normallyCode not defined, or placed mid-messagePaste the definitions block and put the code first
Feedback is too genericNot enough context or inputAdd audience, goal, constraints and the real text
Feedback is too harsh or unhelpfulDefinition too extremeAdd "direct but constructive" and ask for fixes
Output too longNo length constraintAdd "max 5 bullet points" or "under 250 words"
Claude agrees with everythingPrompt invites approvalUse /brutal or /steelman; ask "what is the weakest part?"
Claims seem unverifiedClaude can state plausible but wrong detailsAsk for sources or verify independently

Good practice and limits

Use it wisely

  • Treat output as input. Claude provides a perspective. You make the decision.
  • Verify facts. Check figures, quotes, legal points and citations before relying on them.
  • Protect sensitive data. Do not paste confidential or personal information unless your organisation's policy allows it.
  • Get professional advice for legal, medical, tax and financial decisions. /eli5 helps you understand, not decide.
  • Do not over-rely on harshness. Balance it with what is working well. Ask "what is strong here?" occasionally.

FAQs

Questions answered

Are cheat codes built-in Claude commands?

No. Claude has no hidden /brutal function. It reads the short label, infers your intent and adjusts. Defining each code once makes the results consistent.

Where should I put the definitions?

Paste the block at the start of a chat, or add it to Settings > Personal preferences so it applies to every chat.

Claude ignores my code. What now?

Paste the definitions block and put the code at the very start of your message, followed by your input.

Can I trust the output as advice?

Treat it as input, not a verdict. Verify facts, figures and citations, and get professional advice for legal, medical, tax and financial decisions.

Is it safe to paste confidential material?

Only if your organisation's policy allows it. Avoid pasting confidential or personal information otherwise.
