How to read this SOP

Stack: Claude (Projects, Skills, Connectors/MCP, Scheduled tasks), Kapso for WhatsApp, Composio for social media, and any CRM.

Last verified 6 November 2026 against Anthropic's Help Center and vendor docs. Features change often. Re-check the sources in Section 9 before you sell or deploy anything.

Every claim is tagged so you know how far to trust it.

TagMeaning
VerifiedConfirmed in official docs or the vendor's own page (see Section 9).
Vendor claimStated only on the vendor's marketing or docs page. Test it yourself.
TestNot verified. Test on your own account before relying on it.
Core design rule for all 10 agents
Draft, don't send. Approve, then act. Claude prepares the work and a human approves anything that leaves the building: emails, messages, posts, invoices. This is what makes the "no coding" promise safe and honest.

Section 1

Platform facts that shape every agent

1.1 Gmail, Calendar, Drive, Docs, Sheets

  • VerifiedThe Gmail connector can search and read email, draft emails, and send, reply to and forward emails. By default Claude asks for approval before each send, reply or forward. On Team and Enterprise plans, owners decide whether members can allow these actions to run without asking each time. Older articles saying "draft only" are out of date.
  • VerifiedGmail gives Claude attachment metadata only, not attachment content. Anything that depends on reading an emailed PDF must go through Drive instead.
  • VerifiedGoogle Calendar: view events, create, update and delete events, find mutual availability, manage attendees, set up recurring meetings.
  • VerifiedGoogle Drive: search and read files (Docs, Sheets, Slides, PDFs, images, MS Office files), upload files, create folders, share, move and trash files (approval asked by default).
  • VerifiedDocs, Sheets and Slides are separate connectors from Drive. Turn them on via the plus icon → Connectors → toggle.
  • VerifiedTo get a Google file, name it in the prompt: "Create a Google Doc…", "Create a Google Sheet…". If you ask for a generic "doc" or "spreadsheet," Claude creates a downloadable file instead.
  • VerifiedOn Team and Enterprise plans an Owner must enable the connectors at organization level before users can authenticate. Google Workspace admins may need to mark Claude as a trusted app (admin.google.com → Security → API controls → Manage third-party app access).

1.2 Scheduled tasks

  • VerifiedScheduled tasks have access to your connected tools, skills and installed plugins.
  • VerifiedFrequency options: hourly, daily, weekly, weekdays, or manual (run on demand).
  • VerifiedCreate a task by describing it in chat ("Every Monday at 9 AM, summarize…"), reviewing the proposed name, schedule and instructions, then clicking Schedule. Or go to Scheduled in the sidebar → New task and type / to insert a skill.
  • VerifiedYou can pause, resume, delete, edit and run a task on demand from the Scheduled page, and review past runs.
  • Conflict · testAnthropic's help articles disagree on whether tasks run when your computer is asleep or the desktop app is closed. Newer text says they run remotely. Older text says the desktop app must be open. Check the current article on your account and test with your laptop closed.
  • TestHow "Needs approval" prompts behave when a task runs unattended. Until tested, design scheduled tasks to create drafts and reports, not sends.

1.3 Skills

  • VerifiedA skill is a folder containing a SKILL.md file that starts with YAML frontmatter holding name (max 64 characters) and description (max 200 characters). The description tells Claude when to use the skill.
  • VerifiedPackage: zip the folder so the skill folder is the root of the zip, not a subfolder inside another folder. Upload it, then enable it in Customize → Skills.
  • VerifiedSkills require code execution to be enabled.
  • VerifiedKeep each skill focused on one workflow. Several focused skills compose better than one large one.
  • Note: Anthropic's help text varies the capitalization (skill.md vs SKILL.md). Use SKILL.md, matching Anthropic's published example skills.

1.4 Connectors and custom connectors

  • VerifiedDirectory connectors: Customize → Connectors, click Connect, sign in.
  • VerifiedCustom connectors: Customize → Connectors → Add custom connector, enter a name and the MCP server URL, plus OAuth client ID and secret if the server requires them.
  • Vendor claimFree plans reportedly allow one custom connector. Paid plans remove that limit.
  • Vendor claimIn a connector's tool permissions you can set sending tools to Needs approval instead of Always allow. Do this for every tool that sends, posts, deletes or charges.
  • VerifiedCRM connectors in Claude's directory include HubSpot, Attio, Close and Zoho CRM. Salesforce is a beta directory connector. QuickBooks is a beta connector that can send invoices and run reports. Stripe, Slack, Notion, Calendly and Canva also have connectors.

1.5 WhatsApp and social media

  • VerifiedThere is no native Anthropic WhatsApp connector. Use Kapso's MCP server (Agent 1).
  • VerifiedComposio exposes app connections as MCP tools usable from Claude. Its Facebook toolkit covers Pages only.

1.6 Event-driven triggers (advanced, optional)

  • VerifiedClaude Code routines can be started by a schedule, an API call (each routine gets its own endpoint and token), or GitHub events. They are a research preview with daily run caps that depend on plan.
  • TestNo verified turnkey link from WhatsApp or Kapso to a routine. It would need a tool that can make an HTTP call (Zapier, Make, or Kapso Functions) and is not "no code" in the strict sense.

Section 2

Universal build framework (use for all 10)

Follow these eight steps for every agent. The agent sections in Section 4 only add what is specific to that agent.

Step 1. Create the Project

  1. In Claude, create a new Project named after the agent, for example "Agent 02 Inbox Manager".
  2. Add project knowledge: tone-of-voice guide, pricing, FAQs, templates, ideal-customer profile. Only files this agent needs.
  3. Add project instructions: one paragraph on the agent's role and the "draft, don't send" rule.

Step 2. Connect tools

  1. Go to Customize → Connectors.
  2. Directory apps: click Connect and sign in.
  3. Custom apps (Kapso, Composio): Add custom connector, paste the MCP URL, complete sign-in.
  4. Open each connector's tool permissions. Set every send, post, delete or charge tool to Needs approval.
  5. In each chat, check the plus icon → Connectors and confirm only the needed connectors are on.

Step 3. Write and install the skill

  1. Create a folder named exactly like the skill (for example inbox-manager).
  2. Inside, create SKILL.md using the template below.
  3. Optional: add reference/ files (examples, tone samples, price lists) and mention them in SKILL.md.
  4. Zip the folder so the folder itself is the zip root.
  5. Customize → Skills → upload the zip → enable it.
SKILL.md template
---
name: <max 64 chars>
description: <max 200 chars: what it does + when to use it>
---

# <Skill name>

## When to use
## Inputs (which connectors, sheets, folders, views)
## CRM map            (only if the agent touches a CRM, see Step 6)
## Steps (numbered, in order)
## Output format (exact structure)
## Never do (hard rules)
## If something is missing or fails (say so; never guess)
## Examples (1-2 good outputs)

Step 4. Run manually five times

Run the agent by hand on real data. After each run, edit the skill to fix what went wrong. Do not schedule it until five consecutive runs are acceptable.

Step 5. Schedule it

  1. In chat: describe the task and cadence, review the name, schedule and instructions Claude proposes, click Schedule. Or Scheduled → New task → type / to insert the skill.
  2. Pick the cadence (hourly, daily, weekly, weekdays, manual).
  3. Run it once on demand from the Scheduled page and inspect the output.
  4. Check the run history the next day.

Step 6. CRM-agnostic design

Never hard-code a CRM. Put this block in every skill that touches leads (Agents 3, 5, 8 and 10):

CRM map block
## CRM map (the only block that changes if the CRM changes)
Tool: [HubSpot | Attio | Close | Zoho | Salesforce (beta) | Google Sheet]
Lead list/view: [exact name]
Fields: name, email, company, stage, last_activity, owner, notes
Stale means: no activity in 7 days
Write-back allowed: add a note only. Never change stage or delete.

For a CRM with no Claude connector, use a Google Sheet as the working CRM, or check whether Composio has a toolkit for it.

Step 7. Safety defaults

  • Drafts, not sends. Reports, not actions.
  • Hard caps in the skill (max follow-ups per lead, max leads per run, max posts per day).
  • Every number in a report must name its source. If a source fails, the report says so.
  • A "Never do" list in every skill.
  • Review the first two weeks of outputs daily, then weekly.

Step 8. Test protocol (every agent)

  • Works on a normal case.
  • Works when data is missing or empty (says so, doesn't invent).
  • Respects the "Never do" list when you try to make it break the rules.
  • Output format is exactly as specified.
  • A scheduled run produced the same quality as a manual run.
  • You know where to look when it fails (run history, connector status).

Agent 1

WhatsApp Booking Agent (Kapso)

Purpose: turn inbound WhatsApp requests into confirmed calendar bookings.

Connectors: Kapso (custom), Google Calendar, Google Sheets.

What Kapso provides Verified on Kapso's pages

  • Official WhatsApp Business Platform access (Meta Business Partner).
  • MCP tools: status, whatsapp_numbers, whatsapp_conversations, whatsapp_messages, whatsapp_templates, whatsapp_webhooks, customers, setup_links, search_logs.
  • Number options: a Kapso-provided US number, your own SIM, or an existing WhatsApp Business app (messages sync).
  • Free plan: sandbox number and 2,000 messages a month.
  • Own inbox, visual workflows, broadcasts and serverless functions.

Choose a mode first

Mode A: Claude as operatorMode B: Kapso replies live, Claude supervises
Reply speedNot instant (scheduled, hourly at fastest)Instant (Kapso workflows and webhooks)
SetupNo codeKapso workflow builder, may need some configuration
Claude's jobTriage, draft replies, book, logDaily summaries, template drafting, unanswered-conversation review
CaveatCustomers wait for the next runTestWhich AI model powers Kapso's AI steps is not stated. Don't describe it as "Claude" without checking.

Build steps (Mode A)

  1. Sign up at kapso.com and create a project.
  2. Connect a number. Start with the sandbox and add your own phone to the test session.
  3. In Claude: Customize → Connectors → Add custom connector. Name: Kapso. URL: https://api.kapso.ai/mcp. Sign in through the browser (OAuth). TestKapso documents Claude Code commands; confirm OAuth works in the claude.ai form. Fallbacks: (a) Claude Code with the Bearer API-key header (documented by Kapso), (b) Composio's Kapso toolkit.
  4. Open the connector's tool permissions. Set whatsapp_messages send actions to Needs approval.
  5. Connect Google Calendar and Google Sheets.
  6. Create a Google Sheet "Bookings" with columns: date, time, name, phone, service, status, notes.
  7. Create the skill below and install it.
  8. First test, read-only: ask "Which of my WhatsApp numbers are connected?" then "Which conversations have no reply yet?"
  9. Run end-to-end in the sandbox from your own phone.
  10. Schedule it (prompt below).

Skill: whatsapp-booking/SKILL.md

SKILL.md
---
name: WhatsApp Booking
description: Handles WhatsApp booking requests: checks Calendar availability, proposes slots, books appointments, logs them, and drafts confirmations.
---

# WhatsApp Booking

## When to use
When asked to process new WhatsApp conversations or book an appointment.

## Inputs
- Kapso: whatsapp_conversations, whatsapp_messages
- Google Calendar (availability and event creation)
- Google Sheet "Bookings"

## Business rules (edit these)
Services: [service | duration | price]
Hours: [days and times]
Buffer between appointments: [minutes]
Location / how to prepare: [text]
Languages: [list]

## Steps
1. List conversations with new inbound messages since the last run.
2. For each, identify: wants to book / changing a booking / question / other.
3. For booking requests, check Calendar for free slots matching the service duration plus buffer.
4. Draft a reply offering 2-3 slots. Never offer a slot Calendar shows as busy.
5. When the customer confirms a slot, create the Calendar event and add a row to the Bookings sheet.
6. Draft a confirmation message with date, time, location, preparation notes.
7. Questions you cannot answer from the business rules: flag as NEEDS HUMAN. Do not answer.

## Output
A run summary: conversations reviewed, replies drafted, bookings made, items needing a human.

## Never do
- Never send without approval.
- Never promise prices, discounts, or services not listed above.
- Never double-book.
- Never message a customer who has opted out.

## WhatsApp rules to respect
Free-form replies are only allowed inside WhatsApp's customer-service window; outside it, an approved template is required. If a reply would fall outside the window, draft it as a template suggestion and flag it.

Scheduled task prompt (hourly, during business hours)

Scheduled task
Using the WhatsApp Booking skill, review new Kapso conversations since the last run. Draft replies and prepare bookings, but do not send anything. Give me a summary and a list of items needing a human.

Test checklist

  • Sandbox booking works.
  • A busy slot is never offered.
  • An out-of-scope question is flagged, not answered.
  • The template/window case is handled.
  • Send actions prompt for approval.
Known limits
Not instant in Mode A. Meta's template and window rules apply. Verify Kapso's current pricing before quoting clients.

Agent 2

Inbox Manager

Purpose: triage Gmail, draft replies, and give you a daily digest.

Connectors: Gmail, Google Calendar (optional, for scheduling replies).

Build steps

  1. Create Gmail labels: Urgent, Needs Reply, FYI, Waiting, Newsletter.
  2. Write your triage rules: VIP senders, what counts as urgent, what can be ignored, your tone.
  3. Add 3 to 5 examples of your real replies to the Project knowledge.
  4. Create and install the skill.
  5. Run manually on your last 50 emails. Fix misclassifications in the skill.
  6. Schedule weekdays, morning and mid-afternoon.

Skill: inbox-manager/SKILL.md

SKILL.md
---
name: Inbox Manager
description: Triages Gmail: labels threads, drafts replies in my tone, and produces a daily digest of what needs attention. Never sends.
---

# Inbox Manager

## Inputs
Gmail threads from the last [24 hours / since last run].

## Triage rules (edit)
Urgent: [VIP senders, keywords, deadlines within 48h]
Needs Reply: [a person asked a direct question]
FYI: [no action]
Newsletter: [bulk/promotional]
Ignore: [list]

## Steps
1. Search threads since the last run.
2. Apply one label per thread using the rules.
3. For Needs Reply and Urgent: create a Gmail draft reply in my tone (see reference/tone.md). Keep under [120] words.
4. Flag threads where you lack facts to answer: write "NEEDS INPUT: [what is missing]". Do not guess.

## Output (digest)
1. Urgent (sender, one-line summary, draft ready Y/N)
2. Needs reply
3. Waiting on others (older than 3 days)
4. Counts per label

## Never do
- Never send, forward, or delete.
- Never commit me to dates, prices, or decisions.
- Never open or summarize attachments (Gmail gives metadata only); note "attachment present."

Scheduled task prompt (weekdays, morning and mid-afternoon)

Scheduled task
Using the Inbox Manager skill, triage Gmail since the last run, create drafts for threads needing replies, and show me the digest. Do not send anything.

Test: a VIP email is marked Urgent; a newsletter is not drafted; attachment-only emails are flagged; no sends occur.

Agent 3

Lead Follow-Up

Purpose: find stale leads and draft personalized follow-ups.

Connectors: your CRM (any), Gmail.

Build steps

  1. Decide your CRM and fill in the CRM map. If there is no connector, use a Google Sheet.
  2. Define "stale" and the cadence (for example follow-up 1 after 3 days, 2 after 7, 3 after 14, then stop).
  3. Write 2 to 3 sample follow-ups in your voice into the Project knowledge.
  4. Create and install the skill. Test on 5 real leads.
  5. Schedule weekdays at 9 AM.

Skill: lead-followup/SKILL.md

SKILL.md
---
name: Lead Follow-Up
description: Finds stale leads in the CRM and drafts personalized follow-up emails using the CRM map and cadence rules. Never sends.
---

# Lead Follow-Up

## CRM map
Tool: [fill in]
View: [fill in]
Fields: name, email, company, stage, last_activity, notes
Stale means: no activity in [7] days
Write-back: add a note only.

## Cadence
Follow-up 1: day 3 | Follow-up 2: day 7 | Follow-up 3: day 14 | then stop and tag "Cold".

## Steps
1. Pull stale leads (max [15] per run).
2. For each, read the last interaction and notes.
3. Draft a Gmail email: reference the real last interaction, one clear question, under [100] words.
4. Add a CRM note: "Follow-up N drafted [date]".
5. Skip leads tagged Do Not Contact.

## Output
Table: lead, stage, days stale, follow-up number, draft created Y/N, reason if skipped.

## Never do
- Never send.
- Never invent context, prior conversations, or discounts.
- Never exceed the cadence.

Scheduled task prompt (weekdays, 9 AM)

Scheduled task
Using the Lead Follow-Up skill, find stale leads in the CRM, draft follow-up emails in Gmail, add a note to each lead, and give me the summary table. Do not send.

Test: a lead with no history gets a generic-but-honest draft or is flagged; Do Not Contact leads are skipped; the max cap is respected.

Agent 6

Content Agent (one video becomes a week of posts)

Purpose: turn one video transcript into 7 days of posts, then publish only what you approve.

Connectors: Composio (custom), Google Drive, Google Sheets, Canva (optional).

Composio facts

  • VerifiedComposio exposes connections as MCP tools usable from Claude. Its Facebook toolkit covers Pages only. LinkedIn, Instagram and YouTube toolkits exist.
  • TestPosting tools for TikTok and X: check each toolkit page before promising them.
  • TestMeta (Instagram/Facebook) publishing typically requires a business or creator account linked to a Facebook Page. Confirm in Composio's toolkit docs.

Build steps

  1. Create a Composio account. Link each platform (start with LinkedIn and one other).
  2. Generate the Composio MCP URL for those toolkits.
  3. In Claude: Customize → Connectors → Add custom connector → paste the URL → authenticate.
  4. Set every publish, delete and comment-reply tool to Needs approval.
  5. Create a Google Sheet "Content Calendar": columns date, platform, copy, asset, status, link. Status values: Draft, Approved, Posted, Failed.
  6. Put your voice guide and 3 best-performing posts into the Project knowledge.
  7. Create and install the skill.
  8. Get the transcript: upload to Drive or paste into chat. TestFor automatic YouTube transcript pulls, test a specific Apify Actor first.
  9. Run Task 1 manually on one video, review, set rows to Approved, then run Task 2.
  10. Schedule Task 2 daily.
Optional: reliable timing
Use a tool with its own scheduler so posts publish on time even if a Claude run is missed. Candidates found but not vetted: Postiz (via Composio) and Upload-Post. Verify reliability, pricing and platform coverage first.

# Content Repurposer

See reference/voice.md. Banned words: [list].

Input: transcript.
1. Extract 5-7 distinct ideas, with one memorable line each.

Agent 7

Invoice and Admin Agent

Purpose: keep invoices, receipts and payment follow-ups organized.

Connectors: Google Drive, Google Sheets, Gmail, Stripe and/or QuickBooks (beta, optional).

Critical constraint
Gmail gives Claude attachment metadata only. Receipts and invoices must reach Drive (forward to a monitored Drive folder via your own method, or upload manually). Claude can read PDFs and images in Drive.

Build steps

  1. Create a Drive folder "Inbox - Receipts and Invoices". Decide how files get there.
  2. Create a Google Sheet "Finance Log": date, vendor/client, amount, currency, type (receipt/invoice), status, due date, file link.
  3. Connect Drive, Sheets and Gmail. Connect Stripe or QuickBooks only if needed. QuickBooks is beta: keep invoice creation and sending behind approval.
  4. Create and install the skill. Test on 10 real documents.
  5. Schedule weekly for extraction and overdue review.

Skill: invoice-admin/SKILL.md

SKILL.md
---
name: Invoice Admin
description: Extracts invoice and receipt data from Drive PDFs into a Sheet, flags overdue invoices, and drafts payment reminders.
---

# Invoice Admin

## Steps
1. Read new files in the Drive folder "Inbox - Receipts and Invoices".
2. Extract: date, vendor/client, amount, currency, due date, invoice number.
3. Add each to the "Finance Log" sheet with the file link. If a field is unreadable, write "UNREADABLE" and flag it. Never guess amounts.
4. Check for duplicates (same vendor, amount, number).
5. Find invoices I issued that are unpaid past 7, 14, and 30 days.
6. Draft a payment reminder in Gmail for each (polite at 7, firm at 14, final at 30).

## Output
Summary: files processed, rows added, unreadable items, duplicates, overdue list with draft status.

## Never do
- Never send reminders.
- Never create, edit, or void an invoice in QuickBooks/Stripe without my explicit approval.
- Never guess a number. Flag it.

Scheduled task prompt (weekly, Friday 10 AM)

Scheduled task
Using the Invoice Admin skill, process new files in the receipts folder, update the Finance Log, and draft reminders for overdue invoices. Do not send.

Test: a blurry scan is flagged; a duplicate is caught; reminder tone changes by lateness.

Agent 8

Proposal Agent

Purpose: produce a first-draft proposal from a deal record and your best past proposals.

Connectors: Google Drive, Google Docs, your CRM (any), Gmail.

Build steps

  1. Put 2 to 3 winning proposals, your price list, terms and case studies in the Project knowledge.
  2. Fill in the CRM map (deal fields: client, scope notes, budget, timeline).
  3. Create and install the skill.
  4. Trigger it on demand: "Create a Google Doc proposal for [deal]." Name Google Docs explicitly.
  5. Review and edit. Then ask Claude to draft the cover email in Gmail.

Skill: proposal-writer/SKILL.md

SKILL.md
---
name: Proposal Writer
description: Creates client proposals as Google Docs from CRM deal data and past winning proposals, following our structure and pricing rules.
---

# Proposal Writer

## CRM map
[fill in; read-only]

## Structure
1. Summary of the client's problem (in their words from the notes)
2. Proposed solution and scope
3. Deliverables and timeline
4. Investment (from the price list only)
5. Terms and next steps

## Steps
1. Read the deal record and notes.
2. Draw structure and phrasing from reference/winning-proposals/. Never copy another client's details.
3. Create a Google Doc titled "Proposal - [Client] - [Date]".
4. Price using only reference/price-list. If scope is not covered, write "PRICE NEEDED" and list what is missing.
5. List open questions at the top for me.

## Never do
- Never invent prices, discounts, deadlines, or capabilities.
- Never include another client's name or data.
- Never send the proposal.

Trigger: on demand (not scheduled).

Test: an out-of-scope request produces "PRICE NEEDED"; no leakage from past clients.

Agent 9

Customer FAQ Agent

Purpose: draft accurate answers to common customer questions.

Two modes. Be explicit with clients.

  • Internal drafting (no code, supported here): Claude drafts replies from your knowledge base; a human sends.
  • Public chatbot (not no-code): a customer-facing bot on a website or WhatsApp needs to be built on the Claude API or a helpdesk tool. It is outside this SOP.

Connectors: Gmail, Google Drive or Notion (knowledge base), Kapso (optional, WhatsApp drafts).

Build steps

  1. Build the knowledge base: FAQs, policies, prices, opening hours, shipping and returns, escalation contacts. One source of truth.
  2. Put it in the Project knowledge or a Drive/Notion folder.
  3. Create and install the skill. Test with 20 real past questions, including 5 the knowledge base does not cover.
  4. Schedule weekdays, or run on demand.

Skill: customer-faq/SKILL.md

SKILL.md
---
name: Customer FAQ
description: Drafts customer replies using only the approved knowledge base; escalates anything not covered. Never invents policy or prices.
---

# Customer FAQ

## Source of truth
reference/knowledge-base (and the connected Drive/Notion folder). Nothing else.

## Steps
1. For each customer question, find the answer in the knowledge base.
2. If found: draft a reply in our tone; cite the KB section in an internal note.
3. If not found or ambiguous: write "ESCALATE: [reason]" and do not draft an answer.
4. If the customer is angry, mentions legal action, refunds over [amount], or safety: ESCALATE.

## Never do
- Never invent or assume policy, prices, or timelines.
- Never send.
- Never promise refunds or exceptions.

Scheduled task prompt (weekdays, 10 AM and 3 PM)

Scheduled task
Using the Customer FAQ skill, review unanswered customer emails and draft replies from the knowledge base. Escalate anything not covered. Do not send.

Test: the 5 uncovered questions are escalated, not answered.

Agent 10

Reporting Agent

Purpose: a weekly report on what's working, with sources.

Connectors (choose what you have): Google Sheets, your CRM (any), Stripe, Gmail, social analytics via Composio (for example Facebook post insights, YouTube analytics), Apify for competitor or market data (optional).

Build steps

  1. Define 5 to 7 metrics (for example new leads, bookings, revenue, response time, top-performing post, follow-up reply rate).
  2. For each metric, record the exact source and field in the skill.
  3. Create and install the skill. Run manually for two weeks and verify every number against the source.
  4. Schedule weekly, Monday morning, output to a Google Doc.

# Weekly Reporter

## Metrics (edit)
| Metric | Source | Field/range |
|---|---|---|
| New leads | [CRM] | created this week |
| Bookings | Bookings sheet | rows this week |
| Revenue | Stripe | succeeded payments |
| Best post | [Composio analytics] | top engagement |

## CRM map
[fill in; read-only]

## Steps
1. Pull each metric for this week and last week.

Section 6

Pre-launch checklist (per client or per agent)

  • Project created with only the needed knowledge files.
  • Connectors authenticated; send, post and delete tools set to Needs approval.
  • Skill installed, enabled, and tested five times manually.
  • "Never do" list reviewed by the client.
  • Scheduled task created, run once on demand, output inspected.
  • Failure behavior tested (missing data, disconnected source).
  • Client knows: approval-based, not fully autonomous.
  • Review rhythm set (daily for 2 weeks, then weekly).
  • Client's accounts and credentials are theirs, not yours.

Section 8

Honest positioning for your guide

  • "No coding" is accurate for Agents 2, 3, 4, 6, 7, 8 and 10 (draft-and-review workflows).
  • Agent 1 is no-code in Mode A (not instant). Instant replies use Kapso's own workflow tools, with some configuration.
