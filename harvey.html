Overview

What this SOP covers

Harvey is an open-source (MIT licence) autonomous sales agent. It finds businesses worth selling to, reads their public websites for specific facts, writes cold email that references those facts, sends it after your approval, reads replies and works each conversation toward a meeting.

Model calls run on your Claude Pro or Max subscription through Claude Code, or on a ChatGPT plan through Codex. There is no model API key and no per-token billing.

Purpose

Get a working Harvey installation that finds prospects, drafts compliant cold email and holds every message for your approval.

Who this is for

Founders and operators who run outbound themselves and are comfortable using a terminal.

Tools needed

Python 3.11+, Git, the Claude CLI, a mailbox on a secondary domain and a warmup service. Docker is optional.

02

Install Harvey

Pick one path. Option A is the shortest.

Option A: Let Claude set it up Recommended

  1. Open a terminal in the folder where you keep your projects.
  2. Clone the repository and start Claude Code inside it.
    bash
    git clone https://github.com/ethanplusai/harvey.git
cd harvey
claude
  3. Type set up Harvey for me and press Enter.
  4. Answer the questions Claude asks. It checks your current state, installs what is missing, asks for what it needs and trains Harvey on your product.

Option B: Install manually

  1. Create a virtual environment with Python 3.13 and install Harvey. Use python3.13, not python3, because a venv built from the macOS system Python cannot run Harvey.
    bash
    python3.13 -m venv .venv && source .venv/bin/activate && pip install -e .
  2. Copy the example credentials file.
    bash
    cp .env.example .env
  3. Keep the file open in your editor for step 4. Every variable is documented inline with where to get it.

Option C: Docker on native Linux

  1. Confirm you are on native Linux, you are not logged in as root, and you have already signed in to Claude on the host so ~/.claude exists.
  2. Run the commands below. They build the image, run setup and start the dashboard.
    bash
    git clone https://github.com/ethanplusai/harvey.git
cd harvey
test -e .env || cp .env.example .env
export HARVEY_UID=$(id -u) HARVEY_GID=$(id -g)
docker compose build
docker compose run --rm harvey setup
docker compose up -d
docker compose logs harvey
  3. Open the private unlock link printed in the logs.
  4. Start and stop the heartbeat from the Actions card on the dashboard.
Note

The Docker image ships Claude only, so the Codex provider is not available there. On macOS or Windows use Option A or B. On a remote Linux host, reach the dashboard through an SSH tunnel instead of exposing the port.

Important

Docker mounts the checkout directory at /app. Back up harvey.local.yaml, .env, skills/ and data/ before moving an installation, and restart the container after you edit credentials.

03

Train Harvey on your product

Training reads your website so Harvey writes about what you actually sell. Skip this step if Option A already trained it.

  1. Activate the virtual environment: source .venv/bin/activate
  2. Run the trainer with your product's website address.
    bash
    harvey train https://your-company.com
  3. Wait for it to finish. It writes harvey.local.yaml and generates skills/product_knowledge.md and skills/competitive_intel.md.
  4. Open harvey.local.yaml and check the persona, product description, pricing, and the ICP fields: industries, titles, company size and geography.
  5. Correct anything that is wrong. Re-running the trainer later updates product, targeting and company and keeps your other settings.
Note

If harvey.local.yaml exists it wins over harvey.yaml. It is gitignored, as are both generated skill files, so your positioning and pricing never land in a public repository by accident.

04

Configure credentials and compliance

You are the sender, so set the legal and safety fields before the first campaign.

  1. Open .env and add credentials for your mail provider. The mail provider is the only required variable.
  2. Authenticate your mailbox once.
    • Gmail: harvey gmail auth
    • Microsoft 365: harvey microsoft auth, then harvey microsoft test
    • SMTP: add the SMTP and IMAP details to .env
  3. Add optional keys only for services you will use, such as a search provider for discovery.
  4. Open harvey.local.yaml and set the mail provider, daily cap, approval mode, compliance fields and quota cap.
    yaml
    channels:
  email:
    provider: gmail
    max_daily_sends: 50
    require_approval: true
compliance:
  postal_address: "Your business mailing address"
  do_not_contact:
    - competitor.example
    - jane@customer.example
usage:
  max_daily_claude_percent: 80
  5. Replace postal_address with your real physical mailing address. Harvey adds it and an opt-out line under every cold email and warns you until it is set.
  6. List competitors, existing customers and anyone else Harvey must never email under do_not_contact, one address or domain per line. A domain also covers its subdomains.
  7. Leave require_approval set to true.
  8. Optional: turn on the per-recipient legal check by setting compliance.precleared.enabled to true. Without a key it allows 10 checks a day, and a free key allows 25. Preclearedhttps://precleared.dev
Important

CAN-SPAM requires a truthful subject line, a working opt-out and your postal address. Harvey treats any opt-out wording as immediate and permanent. In the EU and UK, B2B cold email needs a defensible legitimate interest: the pitch must be relevant to that person's role.

If a prospect asks whether they are talking to an AI, Harvey answers truthfully. Never configure it otherwise.

Warning

LinkedIn automation violates LinkedIn's terms of service and can get the account restricted. It is off by default and needs both channels.linkedin.enabled: true and configured credentials. Use an account you can afford to lose. This SOP does not enable it.

None of this is legal advice. If you send at scale or into regulated industries, talk to a lawyer.

05

Confirm your signals

Harvey collects no signal until you confirm it. This is the gate that keeps every prospect list explainable.

  1. Review the catalog. Each signal shows what it means, what it costs and how many companies already carry it.
    bash
    harvey signals
  2. Confirm everything that costs nothing.
    bash
    harvey signals --confirm free
  3. Opt into a paid signal one at a time by naming it.
    bash
    harvey signals --confirm SERP_RANK
  4. Match signals to what you sell. For example, NO_WEBSITE is the highest-intent signal for a website seller, and INCUMBENT_AGENCY shows who holds an account today.
  5. If you confirm HIRING_ROLE, set icp.hiring_signals to the roles that mean a company is buying. The fallback is icp.titles, which names who you email, so it rarely points to the right role.
  6. You can also confirm, skip or reject signals in the dashboard's Signals tab.

Tip

Once signals are confirmed, a cohort is a query. You pick what a prospect must have, what disqualifies them and a range for numeric signals, then the count updates live. Step 9 shows where.

06

Discover businesses

Discovery is the only stage that spends money. It always estimates first and calls nothing until you start it.

  1. List the providers with their real prices.
    bash
    harvey discover --providers
  2. Pick a source using the table below. Start with the free default if you are testing the pipeline.
  3. Project the spend. This prints the estimate and exits.
    bash
    harvey discover --estimate
  4. Run discovery.
    bash
    harvey discover
  5. Selling to startups or hiring companies? Use a preset with a web search provider (Serper or DataForSEO SERP). The presets are yc, accelerator, funding and hiring.
    bash
    harvey discover --preset accelerator --provider serper
  6. Confirm the matching signal (YC_BACKED, ACCELERATOR, FUNDING_ROUND or HIRING_ROLE) in step 5, or profiling will not record it.

Search depth 20 to 30 is enough. Google removed 100 results per page in September 2025, so depth 100 is billed as ten pages, and results below rank 30 are mostly directories.

Note

Harvey never reads ycombinator.com, accelerator directories, Crunchbase, PitchBook or LinkedIn, because their terms forbid scraping. Startup facts come from each company's own site and your search provider.

07

Profile, enrich and verify

These three stages turn a list of names into specific, sendable prospects. They run on their own during harvey run. Run them by hand once to see what Harvey learns.

  1. Run the profiler. It is free: three HTTP requests per business and no model call.
    bash
    harvey profile
  2. Check what it found: the incumbent agency, ad pixels, missing schema, an abandoned blog, open roles and named people. Look in the dashboard's Companies tab.
  3. Understand how owners are chosen. Harvey reads the team, about and contact pages of the company's own site, ranks owners first and keeps at most two people per company.
  4. Understand how addresses are checked. Harvey learns each company's address pattern and verifies one candidate, rather than brute-forcing name variations.
  5. Read each address tag using the table below. Only deliverable addresses are ever sent to.
  6. Optional: export everything Harvey found as a sequencer-ready CSV.
    bash
    harvey export
StatusMeaningSent to?
verifiedConfirmed deliverableYes
riskyThe domain accepts all mail (catch-all)Only if send_to_risky is on
guessPattern-based, unconfirmedNo
invalidRejected or bouncedNo
Note

Harvey is worth running even if you never let it send. Agency detection scores footer wording by confidence and records nothing below 0.5, because a wrong incumbent in an email is worse than saying nothing.

08

Warm up your sending domain

Deliverability is set by the domain, not the copy. Warm up first or burn the domain.

  1. Buy a dedicated sending domain, for example getacme.com rather than acme.com.
  2. Set up SPF, DKIM and DMARC on it. Without all three, Gmail sends your mail to spam.
  3. Sign up for TrulyInbox and add your sending mailbox. API access, which Harvey needs, starts on the Starter plan. TrulyInboxhttps://trulyinbox.com/?via=harvey
  4. In TrulyInbox, open Settings, then API keys, and create a workspace key with these scopes: accounts:read, warmup:read, analytics:read and workspace:read.
  5. Connect the key. Harvey checks it before saving it to .env.
    bash
    harvey trulyinbox connect
  6. Set channels.email.warmup.start_date to the day warmup began. Harvey then sends no cold email for min_days and raises the daily cap by daily_increase each day. Replies always go out.
  7. Check readiness. Replace the domain with yours.
    bash
    harvey warmup getacme.com
  8. Wait until the report ends with READY. It requires the mailbox to be enrolled and signed in, warmed for 14 days by default, with under 5% of warmup mail landing in spam.
  9. Ramp slowly after launch: 10 to 20 emails a day per inbox, adding about 5 a day. Keep warmup running after you start sending.
Warning

Sending cold email from your main domain, or at volume on day one, lands you in spam permanently. The default max_daily_sends: 50 is a ceiling, not a target.

Note

TrulyInbox links in the Harvey project are affiliate links. Already warming with another service? Run harvey trulyinbox other and Harvey stops suggesting it. Harvey only reads from TrulyInbox and never changes your account there.

09

Start Harvey and open the dashboard

The heartbeat runs the work. The dashboard is where you steer it.

  1. Start the heartbeat loop. It wakes every 15 minutes, checks the budget and quiet hours, does the highest-priority job and sleeps.
    bash
    harvey run
  2. Open a second terminal, activate the environment and start the dashboard.
    bash
    harvey dashboard
  3. Open the link it prints. The link carries a private token after the #. The page keeps the token for that browser tab only and removes it from the address bar. Local dashboardhttp://127.0.0.1:5555
  4. If a tab shows a locked screen, print the link again with harvey dashboard --url and open it.
  5. Open the Today tab and finish any setup items it lists. Setup disappears once it is complete.
  6. Learn the sidebar: Work holds Today, Outbox and Conversations. Pipeline holds Signals, Discover, Companies, Contacts and Campaigns. System holds Activity, Usage, Controls, Settings and Help.
  7. Optional: build a cohort in the Signals tab. Choose what a prospect must have, what disqualifies them and a range for numeric signals. The matching count updates live.
Important

The dashboard listens on this machine only and needs the token on every request. To use it from another computer, tunnel instead of exposing it:

bash
ssh -L 5555:127.0.0.1:5555 your-machine

To replace a token, delete data/dashboard-token and restart the dashboard.

10

Review and approve the outbox

By default nothing leaves without you. The Outbox is a decisions desk: one email fills the pane and the rest wait in a rail.

  1. Open the Outbox tab.
  2. Read the email beside what Harvey knew when it wrote it: the company, how the address was found and verified, and the signals the email draws on.
  3. Decide using the keyboard: A approve, E edit, R reject, J and K to move between emails.
  4. Check that the footer shows your opt-out line and postal address.
  5. Check the length. Email 1 stays under 75 words, email 2 under 75 and email 3 under 40.
  6. Optional: set channels.email.send_window with a start and end. The default is 08:00 to 17:00 on weekdays, applied in each recipient's own time zone.
  7. If the Writer gave up on a prospect after 3 unusable drafts, retry it.
    bash
    harvey retry-writes
  8. Optional: review from the terminal with harvey outbox.
Warning

Avoid harvey outbox --approve-all until you have read a few batches. A wall of stacked drafts invites the approve-everything reflex that the approval ladder exists to stop.

Note

Before anything leaves, a pre-send gate with no model involved rejects unrendered merge tags, banned phrases, over-length emails, too many links, HTML bodies, non-deliverable addresses and any mismatch between the recipient and the database record.

11

Handle replies

Harvey classifies each reply, advances the conversation and queues a response through the same approval ladder.

  1. Open the Conversations tab. Threads Harvey handed to you, such as a contract request or a reply it had no safe answer for, appear first.
  2. Read each reply in the context of the emails that led to it.
  3. For a handed-back thread, answer the prospect yourself. Then click Hand back to Harvey to let it continue, or Close to finish it. Reopen brings a closed thread back.
  4. Approve Harvey's drafted replies in the Outbox like any other email.
  5. Respect opt-outs. Any opt-out wording is immediate and permanent, and a later message from that person is never answered. To see why someone was opted out, open Contacts and click Why? on their row.
  6. If an opt-out was a mistake, click Undo opt-out in Contacts. Harvey sends nothing on its own, and their next reply gets a draft for your approval.
  7. Expect Harvey to stop a sequence for everyone at a company when anyone there replies.
  8. Expect Harvey to mark bounced addresses invalid, cancel that prospect's queued sends and trip a global kill switch when the bounce rate passes your threshold.
Note

Conversation stages run in this order: initial_outreach, engaged, qualifying, presenting, negotiating, closing, then closed_won or closed_lost. A listed do-not-contact address that writes back is never answered. The thread comes to you.

12

Monitor, pause and export

Check these on a regular schedule while Harvey runs.

  1. See the pipeline state and what Harvey is doing now.
    bash
    harvey status
  2. Check quota use and per-agent token counts. There are no dollar figures because you are on a subscription.
    bash
    harvey usage
  3. Watch the Activity tab. Every decision Harvey makes is logged in the actions table.
  4. Check the bounce rate each week. Above about 3%, stop and fix list quality.
  5. Pause all outbound mail while the loop keeps running, then resume when ready.
    bash
    harvey sending pause
harvey sending resume
  6. To stop everything, press Ctrl + C in the harvey run terminal. State lives in SQLite, so Harvey resumes cleanly.
  7. Export deliverable prospects to CSV with harvey export. Opted-out contacts are excluded.
Warning

harvey export --all is a raw export for inspection. It includes opted-out and unverified contacts. Never import it as an outreach list.

13

Optional: use a ChatGPT plan instead of Claude

Claude is the default. Switch only if you would rather spend a ChatGPT plan through the Codex CLI. It is still a subscription, never per-token API billing.

  1. Confirm you are on macOS or Linux. Windows and Docker are not supported for Codex.
  2. Install the exact Codex version Harvey has verified and sign in with ChatGPT. API-key logins are refused.
    bash
    npm install -g @openai/codex@0.159.3
codex login
  3. Choose Codex in harvey setup, or add this to your config file.
    yaml
    brain:
  provider: codex
  model: gpt-5.5
  reasoning_effort: ""
  4. Optional: train with Codex by running harvey train https://your-company.com --provider codex --model gpt-5.5.
  5. Check that Codex is usable without sending a prompt.
    bash
    harvey status --check
Warning

Harvey uses exactly one provider and never falls back to Claude or an API key. Any Codex version other than 0.159.3 is refused, including newer ones. If Codex cannot be used, Harvey skips the whole cycle and shows "Codex paused" with the reason. Fix the cause, usually codex login, and Harvey resumes on its next heartbeat.

Note

Harvey runs Codex in a private temporary home with every tool disabled, so your own Codex configuration is never loaded or changed. Set brain.model to an exact model ID from your account's catalog. A blank value selects the highest-priority listed model that works with this setup.

14

Optional: turn on autopilot

Autopilot sends first emails, follow-ups and replies on schedule without waiting for each approval. The daily limit, quiet hours, warmup ramp, opt-outs, bounce handling and the pause switch all still apply.

  1. Approve a batch or two by hand and read what Harvey writes before going further.
  2. Turn it on in the dashboard: Settings, then Sending, then Turn on autopilot, and type autopilot to confirm. Or set channels.email.require_approval to false in your config. A running Harvey picks it up on its next cycle.
  3. Know what stays held for you. An email nobody approved goes back to the Outbox, marked Held with the reason, when it:
    • links to, or gives an address at, a domain that is not yours
    • quotes a passage of Harvey's own instructions from prompts/ or skills/
  4. Add trusted domains under channels.email.link_domains if Harvey should be allowed to link to them.
  5. Review held emails one by one. Approve all leaves them out on purpose.
  6. Turn autopilot off at any time with one click on Turn off autopilot, or set require_approval back to true. Emails autopilot approved that have not gone out return to the Outbox at once.
Warning

Websites Harvey researches and replies people send can carry planted instructions. Harvey marks that text as data and the model has no tools to act with, but a prompt cannot guarantee it ignores an instruction. That is why held emails exist.

Note

On Instantly, the local Outbox cannot approve individual sends. With approval on, Harvey holds campaign deployment and routes replies to a human. Use Gmail, Microsoft 365 or SMTP for the approval queue. Pausing autopilot does not pause campaigns already running in Instantly. Pause those there.

15

Optional: edit the skills library

Harvey's sales knowledge is plain Markdown in skills/. There is no fine-tuning and no vector store. Before an agent runs, the skills it needs are joined into its prompt, so an edit changes the next heartbeat with no restart.

  1. Decide what to change. If emails feel too pushy, edit email_frameworks.md. If Harvey mishandles an objection, edit objection_handling.md and add the response you would actually give.
  2. Open the file in skills/ and make the edit.
  3. Save it. The next heartbeat uses the new wording.
  4. To add a new skill, write the file, then add its name to skill_map in harvey/brain.py. The same map controls which agent receives which skill.
  5. Optional: set writer.humanizer to true to add one editing pass per batch, using ~/.claude/skills/humanizer/SKILL.md.

FAQs

What is Harvey?

Harvey is an open-source autonomous sales agent. It finds businesses, learns something specific about each one from its public website, writes cold email that references it, sends after your approval, reads replies and works the conversation toward a meeting.

Does Harvey need a model API key or per-token billing?

No. Model calls go through your Claude Pro or Max subscription using Claude Code, or a ChatGPT plan using Codex. Your plan's usage limits still apply, and Harvey throttles itself to leave headroom for your own work.

Does Harvey send email without my approval?

Not by default. Every outgoing email waits in the Outbox until you approve it. Autopilot is opt-in, and even then a pre-send gate and the Held queue apply.

How long should a new sending domain warm up?

Warm up for 2 to 4 weeks before real volume and keep warmup running afterward. Start at 10 to 20 emails a day per inbox and add about 5 a day.

How much does it cost to run?

Model calls use your existing subscription. Discovery is free on the default source or about $0.37 per 1,000 on the cheapest paid one, and reading websites is free. You also pay for a mailbox, about $7 a month for Google Workspace, and a warmup service.

Where does my data live?

Everything is local: data/harvey.db, .env and your config files. Nothing leaves your machine except calls to the services you configure.

Can Harvey make cold calls?

No. A fully autonomous AI cold dialer is not planned. Any voice feature will be limited to consent-gated inbound and opt-in callbacks.

Which mail providers work?

Gmail or Google Workspace, Microsoft 365, and SMTP with IMAP all support the approval queue. Instantly is supported as a legacy option and cannot hold individual emails for approval.
