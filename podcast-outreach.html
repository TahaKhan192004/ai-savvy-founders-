What this SOP builds

This SOP sets up an AI agent built with Claude that runs podcast guest outreach from first search to booked interview. The agent does the research and repetition. You do the conversations.

  • Finds podcasts that match your niche and audience size
  • Pulls host details and recent episodes so every pitch references something real
  • Writes a personalized pitch for each show
  • Sends it and tracks who replied
  • Sends follow-ups on a schedule until there is an answer
  • Drops your booking link when a host says yes

Purpose

Why split the work between an agent and a human

About 80% of podcast outreach is research and repetition. That part does not need a person. The conversation does.

The agent opens the door. You walk through it. Use this SOP when you want a steady flow of podcast pitches that never skips a follow-up and never sounds copy-pasted.

  2. Wait to connect Gmail until you finish Step 3.

  4. Send this message to confirm the connectors are available in the session: List the connectors you can use right now.
  5. Fix any missing connector before you go on.

How it runs

Scheduled tasks replace a workflow tool

Each stage of the agent is one Claude scheduled task, also called a routine. It wakes on its schedule, does one job, and writes the result to Supabase.

  1. Every run starts in a fresh session with no memory of earlier runs.
  2. Each task prompt therefore begins by reading its settings and state from Supabase.
  3. Each task ends by writing its results back to Supabase.
  4. Supabase is the agent memory. Anything not saved there is forgotten.
TaskScheduleJob
Podcast DiscoveryDailyFinds and saves new shows (Step 4)
Host EnrichmentDaily, after DiscoveryAdds host, episodes, verified email (Step 5)
Pitch WriterDaily, after EnrichmentDrafts one pitch per ready show (Step 6)
SenderHourlySends approved pitches inside the daily cap (Step 8)
Reply WatcherHourlyFinds replies, classifies them, hands off (Steps 8 and 10)
Follow-up EngineDailySends the next touch where no one replied (Step 9)
Weekly ReportMondaysEmails you the numbers (Step 11)
Important

Nobody is watching a scheduled run, so a run that needs approval will stall. Keep the Sender task on ask-first until you finish Step 7. After that, switch each task to automatic approval in its settings, if your organization allows it.

01

Define your guest profile and offer

You do this once

Every task reads this profile on every run. Everything the agent writes comes from here.

  1. In your podcast-outreach folder, create a file named guest_profile.json.
  2. Fill in your identity fields
    1. Add your name exactly as you want it to appear in pitches
    2. Write a two sentence bio with one piece of proof
    3. Paste your booking link
    4. Add the email address that should receive your alerts
  3. Write 2 to 4 topic angles. Each angle needs a title and a one line description of what you would teach on air.
  4. Add niche keywords the agent will search for.
  5. Set the show filters: minimum rating count, minimum episode count, language, and maximum days since the last episode.
  6. Add exclusions, such as pay-to-play shows and shows that never host guests.
  7. Set your send window: weekdays, start time, end time, and time zone.
  8. Set the daily send cap to 10 for now. You raise it in Step 3.
JSON 
{
  "guest_name": "Your Name",
  "bio": "Two sentences on who you are and the proof behind your topic.",
  "booking_link": "https://your-booking-link.com",
  "alert_email": "you@yourdomain.com",
  "niche_keywords": ["ai automation", "small business", "founders"],
  "topic_angles": [
    { "title": "Angle one", "one_liner": "What you would teach on air." },
    { "title": "Angle two", "one_liner": "A second, different lesson." }
  ],
  "filters": {
    "min_ratings": 25,
    "min_episodes": 20,
    "language": "en",
    "max_days_since_last_episode": 45
  },
  "exclusions": ["pay to play", "no guest episodes"],
  "send_window": {
    "days": "Mon-Fri",
    "start": "09:00",
    "end": "17:00",
    "timezone": "Your/Timezone"
  },
  "daily_send_cap": 10
}
Important

Podcast audience size is rarely public. The agent uses proxies instead: rating count, episode count, and how often the show publishes. Tune these numbers after your first batch.

02

Set up the database with Claude Code

You paste one prompt

Claude Code builds the tables through the Supabase connector. You never open the SQL editor.

  1. Open Claude Code in your podcast-outreach folder with the Supabase connector enabled.
  2. Paste the prompt below and send it.
  3. When Claude asks which Supabase project to use, pick one from the list. Approve the cost only if you ask Claude to create a new project.
  4. Let Claude apply the schema as a migration, so the change is tracked and repeatable.
  5. Read Claude's report. It should list five tables and confirm row level security is on for each.
  6. Ask Claude to run the security advisors and fix anything they flag.
  7. Send this follow-up: Save guest_profile.json into the config table under the key guest_profile, then read it back and confirm the values match.
Prompt 
Use the Supabase connector to set up the database for my podcast
outreach agent.

1. List my projects and ask which one to use. Do not create a new
   project without asking me first.
2. Apply the SQL below as a migration named
   create_podcast_outreach_tables.
3. Enable row level security on every table. Add no public policies.
4. List the tables to confirm all five exist.
5. Run the security advisors and fix anything they flag.
6. Report the table names and the advisor result.

SQL:

create table config (
  key text primary key,
  value jsonb not null,
  updated_at timestamptz default now()
);

create table shows (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  rss_url text unique,
  website text,
  host_name text,
  host_email text,
  email_status text default 'unverified',
  rating_count int,
  episode_count int,
  last_episode_at timestamptz,
  status text default 'discovered',
  created_at timestamptz default now()
);

create table episodes (
  id uuid primary key default gen_random_uuid(),
  show_id uuid references shows(id) on delete cascade,
  title text,
  summary text,
  url text,
  published_at timestamptz
);

create table outreach (
  id uuid primary key default gen_random_uuid(),
  show_id uuid references shows(id) on delete cascade,
  stage text default 'drafted',
  angle_used text,
  approved boolean default false,
  next_action_at timestamptz,
  last_reply_class text,
  created_at timestamptz default now()
);

create table messages (
  id uuid primary key default gen_random_uuid(),
  outreach_id uuid references outreach(id) on delete cascade,
  channel text default 'email',
  direction text check (direction in ('out', 'in')),
  subject text,
  body text,
  thread_id text,
  sent_at timestamptz default now()
);

alter table config enable row level security;
alter table shows enable row level security;
alter table episodes enable row level security;
alter table outreach enable row level security;
alter table messages enable row level security;
Stage valueMeaning
draftedPitch written, waiting for approval
needs_reviewPitch failed the quality gate twice, waiting for you
approvedCleared to send
sentFirst email delivered
followup_1, followup_2, followup_3Follow-up number sent
repliedHost answered
bookedInterview date confirmed
closedNo answer, no, or opted out
suppressed (on shows.status)Never contact this show again
Warning

With row level security on and no public policies, the tables stay private to your connector. Do not add open policies to make something work.

03

Prepare your sending domain and inbox

You do this once

Protect your main domain. Outreach goes out from a separate one.

  1. Register a secondary domain that clearly relates to your brand. Do not send outreach from your main business domain.
  2. Create one mailbox on that domain in Google Workspace, using your real name.
  3. Add the DNS records at your domain provider
    1. SPF record
    2. DKIM record from your mail provider
    3. DMARC record with a monitoring policy to start
  4. Add an email signature with your full name, role, and a link to your real website.
  5. Set a reply-to address you check daily.
  6. Warm up the mailbox for two weeks before full volume. Send real conversations between inboxes you control, then increase pitch volume using the table below.
  7. Connect the Gmail connector to Claude using this outreach mailbox.
  8. Each week, ask Claude Code to update daily_send_cap in the config table to match the table.
WeekDaily pitch cap
Week 110
Week 220
Week 3 and after30 (hold here unless bounce and complaint rates stay low)
Warning

Every pitch needs your real name, a real way to reach you, and a one line opt-out. Honor opt-outs immediately. Cold email rules vary by country, so check yours before you send.

04

Build podcast discovery

Agent runs this daily

A scheduled task searches for shows that fit your niche, filters them, and saves the keepers.

  1. Pick the scraper once. In Claude Code, send this: Use the Apify connector to search the Apify Store for podcast directory scrapers. Compare the top results by usage, read the input schema of the best one, and save its actor ID in the config table under the key podcast_actor.
  2. Confirm the saved actor ID in the config table. Every run now uses the same actor.
  3. Create a scheduled task named Podcast Discovery that runs once a day.
  4. Paste the prompt below as the task prompt.
  5. Run the task once by hand.
  6. Open the shows table and confirm at least 20 new rows with status = discovered.
Prompt 
You are the Podcast Discovery task for my podcast outreach agent.
Each run starts fresh, so read everything you need from Supabase.

1. Read the config rows guest_profile and podcast_actor.
2. Use the Apify connector to run the saved actor. Read its input
   schema first. Use my niche_keywords as the search terms.
3. Drop any show that fails my filters: min_ratings, min_episodes,
   language, max_days_since_last_episode.
4. Drop any show that matches my exclusions.
5. For each remaining show, read the last five episode titles and
   decide true or false: does this show interview outside guests?
   Drop the false ones.
6. Skip any show whose rss_url already exists in the shows table.
7. Insert each new show with status discovered.
8. Stop after 50 new shows in one run.
9. Finish with one line: shows found, shows dropped, shows saved.
Tip

Start with narrow keywords. Fifty well-matched shows beat five hundred loose ones. Widen the search only after your first reply data comes in.

05

Enrich host details and recent episodes

Agent runs this daily

This step is why each pitch can reference something real.

  1. Create a scheduled task named Host Enrichment that runs once a day, an hour after Podcast Discovery.
  2. Paste the prompt below as the task prompt.
  3. Run it once by hand and check five shows in the shows table
    1. Each has a host name
    2. Each ready show has an email marked verified
    3. Each has three rows in the episodes table
  4. Open any show marked needs_manual_email and add the address yourself if you can find one.
Prompt 
You are the Host Enrichment task. Each run starts fresh, so read
everything you need from Supabase.

1. Select up to 25 shows with status discovered.
2. For each show, fetch the RSS feed at rss_url.
3. Save the host or author name on the show. Save the last three
   episodes (title, summary, link, publish date) into episodes.
4. If the feed lists no host name, fetch the show website and look
   for a host or about page.
5. Use the Apollo connector to look up the host by name and the show
   website domain.
6. Set email_status to verified only when Apollo returns the address
   with a verified status. Set anything else to unverified. Never
   guess an address from a pattern.
7. Set status ready for verified shows. Set status needs_manual_email
   for the rest.
8. Finish with one line: shows ready, shows needing a manual email,
   and the Apollo credits spent.
Warning

Apollo lookups spend credits, which is why the task stops at 25 shows per run. Check your Apollo balance weekly. Never send to an address Apollo did not verify, because bounces damage your sender reputation fast.

06

Generate the personalized pitch

Agent writes, quality gate checks

Claude writes one pitch per show from your profile, the host, and a real recent episode, then checks its own work before saving.

  1. Create a scheduled task named Pitch Writer that runs once a day, an hour after Host Enrichment.
  2. Paste the prompt below as the task prompt.
  3. Run it once by hand.
  4. Open the outreach table and confirm each new row has stage = drafted or stage = needs_review.
  5. Open the messages table and read three drafts. Each must name a real episode title from that show.
Prompt 
You are the Pitch Writer task. Each run starts fresh, so read
everything you need from Supabase.

SETUP
1. Read the config row guest_profile.
2. Select up to 25 shows with status ready that have no outreach
   row yet.
3. For each show, load its three most recent episodes.

WRITE
For each show, write one pitch as the guest_name from my profile,
using these rules.
1. Reference one specific recent episode by its exact title and say
   what it made you think of.
2. Offer one topic angle only, the one that best matches that
   episode.
3. Keep the body under 150 words.
4. Never open with a general compliment about the show.
5. Write in first person. Plain language. No hype words.
6. End with one question the host can answer in one line.
7. Do not include any booking link in this email.
8. Finish with one sentence telling the host they can reply
   "no thanks" and you will not email again.

QUALITY GATE
Fail the pitch if any of these is true.
- The body is over 150 words
- The episode title you referenced is not in the episodes table
  for this show
- It contains "I love your podcast", "big fan", or "game-changing"
- It contains my booking link
On a fail, rewrite once. If it fails again, save it with stage
needs_review.

SAVE
Insert an outreach row with stage drafted and angle_used. Insert
the subject and body into messages with direction out.
Finish with one line: pitches written, pitches sent to needs_review.
Important

The booking link stays out of the first email on purpose. The agent sends it only after the host says yes, in Step 10.

07

Approve the first batch

You do this before anything sends

The first 25 pitches decide how good the next 500 will be. Read every one, in a review session with Claude Code.

  1. Open Claude Code in your podcast-outreach folder.
  2. Paste the review prompt below.
  3. For each pitch Claude shows you, answer with one of three words
    1. approve: Claude sets approved = true and stage = approved
    2. edit: tell Claude the change, then it saves the new text and approves
    3. reject: Claude sets stage = closed and notes why
  4. Write down every repeated edit you make.
  5. Ask Claude to add each repeated edit as a new rule in the Pitch Writer task prompt.
  6. Run a second batch of 25 and repeat.
  7. Switch to spot checks when fewer than 2 of 25 pitches need edits. From then on, review 5 random pitches per day before the send window.
  8. After the second clean batch, switch your tasks to automatic approval in their settings, if your organization allows it.
Prompt 
Use the Supabase connector. Show me the first 25 outreach rows with
stage drafted, one at a time. For each one show the show name, the
host, the episode referenced, the subject, and the body. After each
one I will say approve, edit, or reject. Apply my answer to the
database before showing the next one.
Tip

Judge each pitch with one question: would a host think you actually listened to that episode? If the answer is no, the pitch does not go out.

08

Send and track every message

Agent runs this hourly

Approved pitches go out inside your daily cap. Every send is logged against its email thread, and a second task watches for replies.

  1. Create a scheduled task named Sender that runs hourly.
  2. Paste the Sender prompt below. Keep this task on ask-first until Step 7 is finished.
  3. Create a second scheduled task named Reply Watcher that runs hourly.
  4. Paste the Reply Watcher prompt below. You extend it in Step 10.
  5. Approve two test pitches that go to an inbox you control.
  6. Run the Sender by hand and confirm
    1. Both emails arrive from the outreach mailbox
    2. The thread_id is saved in messages
    3. The stage is sent and next_action_at is four days out
  7. Reply to one test email, then run the Reply Watcher by hand and confirm the stage becomes replied.
Prompt 
You are the Sender task. Each run starts fresh, so read everything
you need from Supabase.

1. Read the config row guest_profile for daily_send_cap and
   send_window.
2. If the current time is outside the send window, stop.
3. Count the messages with direction out sent today. If the count
   has reached daily_send_cap, stop.
4. Select outreach rows with stage approved, oldest first, up to
   the remaining cap. Skip any show whose status is suppressed.
5. Use the Gmail connector to send each pitch to the host_email as
   a new thread.
6. After each send, save the Gmail thread_id on the message, set
   stage sent, and set next_action_at to four days from now.
7. Finish with one line: pitches sent, daily cap remaining.
Prompt 
You are the Reply Watcher task. Each run starts fresh, so read
everything you need from Supabase.

1. Select outreach rows with stage sent, followup_1, followup_2, or
   followup_3, with their saved thread_id values.
2. Use the Gmail connector to check each thread for new messages
   from the host.
3. For each new host message, save it to messages with direction in
   and set stage replied. This stops all follow-ups for that show.
4. Search the inbox for bounce notices from the last day. Match each
   one to a show, set email_status invalid, and set stage closed.
5. Finish with one line: replies found, bounces found.
Note

Replies are the real signal. Open tracking is approximate because many mail apps load images automatically, so this setup does not depend on it.

09

Schedule follow-ups

Agent runs this daily

Follow-ups are where most bookings come from, and where humans forget. The agent never forgets.

TouchTimingWhat it does
First pitchDay 0Episode reference, one angle, one question
Follow-up 1Day 4Short bump that adds one new detail about the angle
Follow-up 2Day 9References a newer episode if one has dropped
Follow-up 3Day 16Polite last note that closes the loop
  1. Create a scheduled task named Follow-up Engine that runs once a day, in the morning of your send window.
  2. Paste the prompt below as the task prompt.
  3. Move one test row forward by asking Claude to set its next_action_at to yesterday.
  4. Run the task by hand and confirm the follow-up arrives in the same email thread and the stage becomes followup_1.
Prompt 
You are the Follow-up Engine task. Each run starts fresh, so read
everything you need from Supabase.

1. Read the config row guest_profile for daily_send_cap and
   send_window. If the current time is outside the send window, stop.
2. Select outreach rows where next_action_at is today or earlier,
   stage is sent, followup_1, or followup_2, and no message with
   direction in exists. Skip any show whose status is suppressed.
   Respect the daily cap together with the Sender task.
3. For each row, load the full message history. Check the show RSS
   feed for an episode newer than the one already referenced.
4. Write the next touch.
   - stage sent: follow-up 1, a short bump that adds one new detail
     about the angle
   - stage followup_1: follow-up 2, referencing a newer episode if
     there is one
   - stage followup_2: follow-up 3, a polite last note that closes
     the loop
5. Use the same voice. Never repeat a line from an earlier message.
   Keep it under 100 words. No booking link.
6. Apply the same quality gate as the Pitch Writer task.
7. Use the Gmail connector to send it in the same thread.
8. Update the row.
   - After follow-up 1: stage followup_1, next_action_at in 5 days
   - After follow-up 2: stage followup_2, next_action_at in 7 days
   - After follow-up 3: stage closed, next_action_at in 90 days
9. Finish with one line: follow-ups sent by touch number.
Important

The sequence stops on any reply, bounce, opt-out, or manual pause. Each stop condition is a hard check in the prompt before anything sends.

10

Classify replies and hand off

The handoff point. A human takes over here

Every inbound message gets a label. A clear yes gets your booking link and an immediate alert to you.

  1. Open the Reply Watcher scheduled task and edit its prompt.
  2. Paste the block below at the end of the prompt, after step 5.
  3. Save the task and run it by hand against your test reply from Step 8.
  4. Reply to a test email with a clear yes. Run the task again and confirm
    1. The label is interested
    2. A reply with your booking link goes out in the same thread
    3. You receive an alert email at your alert address
  5. From this point on, you reply to that host yourself.
Prompt 
CLASSIFY AND ACT
For each new host message, give it one label:
interested, question, not_now, no, auto_reply, unsubscribe.
Use interested only when the host clearly wants to talk or book.
If unsure between interested and question, choose question.
Save the label in outreach.last_reply_class and write a one
sentence summary of what the host said.

Then act on the label.
- interested: use the Gmail connector to reply in the same thread,
  thank the host, and include booking_link from my profile. Then
  email my alert_email with the show name, the host's message, and
  a link to the thread.
- question: draft a reply in my voice and email it to my
  alert_email for approval. Do not send it to the host.
- not_now: set stage paused and email my alert_email the date the
  host gave, if any.
- no: set stage closed and set the show status suppressed.
- auto_reply: ignore it.
- unsubscribe: set stage closed and set the show status suppressed
  right away.

BOOKINGS
Search Gmail for booking confirmation emails from my calendar tool
received since the last run. Match each to a show, set stage
booked, and email my alert_email a prep note with the show name,
the interview date, and the episode referenced in the pitch.
LabelAction
interestedAgent sends the booking link and alerts you. You take over
questionAgent drafts a reply for you. You approve and send
not_nowSequence pauses. You restart it when the host is ready
noClose the outreach and suppress the show
auto_replyIgnore it and keep the schedule
unsubscribeClose immediately and suppress the show permanently
11

Review results every week

You do this weekly

A weekly report lands in your inbox. Fifteen minutes with it keeps the system sharp.

  1. Create a scheduled task named Weekly Report that runs every Monday morning.
  2. Paste the prompt below as the task prompt.
  3. Each Monday, open the report and compare it with the table below.
  4. Ask Claude Code to show you five recent replies of any kind. Note the language hosts use.
  5. Adjust one thing only
    1. Topic angles, if replies show the wrong fit
    2. Show filters, if hosts say the show does not take guests
    3. The Pitch Writer prompt, if pitches read generic
    4. The daily cap, if bounces or spam complaints rise
  6. Write the change and the date in the version history at the bottom of this SOP.
Prompt 
You are the Weekly Report task. Each run starts fresh.

1. Use the Supabase connector to count, for the last 7 days:
   pitches sent, replies by label, bounces, and interviews booked.
2. Work out the reply rate, the interested rate (interested
   replies divided by pitches sent), and the bounce rate.
3. List the five most recent replies with show name and label.
4. Email the summary to alert_email from the config row
   guest_profile. Plain language, under 200 words.
MetricHow to read it
Pitches sentShould match your daily cap times send days
Reply rateSet your own baseline after your first 100 sends
Interested rateReplies labeled interested, divided by pitches sent
Bounce rateKeep under 3%. Above that, pause and review Step 5
Interviews bookedThe only number that counts in the end

  4. Alert yourself when the person shows a buying signal or asks a direct question.

FAQs

Common questions

What does a podcast outreach AI agent do?

It finds podcasts that match your niche, pulls host details and recent episodes, writes a personalized pitch for each show, sends it, tracks replies, sends scheduled follow-ups, and drops your booking link when a host says yes.

Do I need n8n or other workflow software?

How many podcast pitches should the agent send per day?

Start at 10 per day for the first week, move to 20 in week two, and cap at 30 per day from week three. Keep the cap low enough to protect your sender reputation.
