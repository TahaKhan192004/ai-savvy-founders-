Build a landing page with Claude: the full workflow

You can have a real landing page live this week, built by Claude, with one clear job: get a visitor to take one action. No code, no developer, no template to wrestle with.

This guide works in the Claude desktop app (the Code tab) and on the web at claude.ai/code. The desktop route is easier for a first page, because Claude works on a folder already on your computer and shows you a live preview as it builds.

Plan on roughly 60 to 90 minutes for a first draft you like, and another 30 minutes to put it online. Those times are an estimate, not a promise. A longer offer or more photos adds time.

Before you start

What you need

Use the desktop app if you can. It only needs a folder on your computer, while the web version needs a GitHub repository first.

Claude Code needs a paid Claude plan (Pro, Max, Team or Enterprise). The desktop app runs on macOS and Windows, and Linux is in beta. You do not need to install anything else, because Claude Code is built into the Code tab.

Desktop app (Local)Web (claude.ai/code)
Where Claude worksA folder on your computerA cloud copy of a GitHub repository
Extra accountsNoneA GitHub account
Seeing your pageBuilt-in preview inside the appReview the saved files, or deploy a preview through your host
Best forYour first page, fast editsWorking from a browser or phone, longer tasks

Have these ready

  • Your logo as a PNG or SVG file
  • Brand colours as hex codes (like #1F3A5F), or a screenshot of where they appear
  • Three to six photos, including a clear photo of you
  • Your offer written out in your own words, even roughly
  • Your booking link, or the place where form details should go
  • Testimonials, if you have them, with the name each person is happy to show

01

Step 1 of 10

Pick one goal

A landing page works because it asks for one thing. Choose the single action you want a visitor to take, and everything on the page will point at it.

If your goal isThe button saysWhat it connects to
Book a callBook your free callYour calendar link
Get a freebieSend me the guideA form tool or email platform
Join a waitlistSave my spotA form tool or email platform
Buy a low-cost offerGet instant accessA checkout link

Write your goal as one sentence before you move on: "The goal of this page is to get [who] to [do what]." Claude will use this sentence to decide what stays and what goes.

One button

A second button that does something different splits attention. If you want both a call and a freebie, build two pages.

02

Step 2 of 10

Build your brand folder

The better the folder, the less Claude has to guess. Make one new folder on your computer, name it something simple like landing-page, and organise it like this:

Folder layout
landing-page/
  offer.md
  testimonials.md
  brand/
    logo.png
    colours-and-fonts.md
  photos/
    me.jpg
    (any other photos)
  references/
    page-i-love-1.png

You can write the .md files in Notepad, TextEdit or any notes app and save them with that ending. If that feels fiddly, paste your notes into a normal chat with Claude and ask it to tidy them into an offer.md file, then save the result into the folder.

What goes in offer.md

Copy this template and fill in what you know. Rough answers are fine. A gap is better than a guess.

offer.md template

One sentence on what it is:
Price or "free":

WHO IT IS FOR
The person I help:
Who it is not for:

THE PROBLEM
What they are struggling with, in their own words:
What they have already tried:

THE RESULT
What changes for them after working with me:
How long it takes:

HOW IT WORKS
Step 1:
Step 2:
Step 3:

PROOF
Results, numbers, years of experience, logos, press:

ABOUT ME
My story in 4 or 5 sentences:

QUESTIONS I ALWAYS GET
Q and A (write 4 to 6):

THE GOAL OF THIS PAGE
The one action I want people to take:
The link for that action:

THINGS TO AVOID
Words, claims or promises I do not want on the page:

What goes in the other files

  • colours-and-fonts.md: your main colours as hex codes, the fonts you use if you know them, and two or three words for the feel you want (warm, calm, bold, clean).
  • testimonials.md: each quote exactly as the person said it, with their name and role. Only add real ones.
  • photos: name them clearly (me-smiling.jpg beats IMG_4821.jpg) so you can say "use me-smiling.jpg in the hero" later.
  • logo: if you have a version for dark backgrounds, add it and name it logo-white.png.
03

Step 3 of 10

Open Claude Code on your folder

On the desktop app, this takes about two minutes. On the web, you first put your folder into a GitHub repository. Follow the route you chose.

Desktop app (recommended)

  1. Download the Claude desktop app from claude.com/download, install it and sign in.
  2. Click the Code tab at the top of the sidebar. If you only see icons, hover over them to find it.
  3. Under the prompt box, click the first control (the environment selector) and pick Local.
  4. Click the project folder control beside it and choose Open folder (older versions say Select folder). Pick your landing-page folder.
  5. Open the model picker on the right of that row and choose the strongest model your plan offers. You can switch any time.
  6. Check the permission mode in the same row. Manual asks before every change, Accept edits lets Claude save changes and shows you what changed, and Plan lets Claude propose without touching your files.
Tip

Start in Manual if you want to see each change. Switch to Accept edits once you trust how it works, because approving every small edit slows you down.

Web app

  1. Create a free GitHub account if you do not have one, then create a new repository. Choose Private, since your photos and testimonials are in there.
  2. Upload your folder's files to that repository using GitHub's "Add file" then "Upload files" option in the browser.
  3. Go to claude.ai/code and sign in.
  4. When it asks, install the Claude GitHub App and give it access to that one repository.
  5. Pick the repository and send your first prompt.

On the web, Claude works on a cloud copy and saves its changes to a branch in your repository. Merging that branch on GitHub is how the changes reach your main version. If that word is new to you, ask Claude:

Prompt
Explain what I need to click on GitHub to approve your changes, step by step.
04

Step 4 of 10

Send the first prompt

Your first message should do three things: tell Claude to read everything, state the goal, and invite questions before it builds. Paste this and change the goal in brackets.

First prompt
Read every file in this folder, including the images in brand/, photos/ and references/.

I want a landing page for the offer described in offer.md. The goal of the page is to get people to [book a call / join the waitlist / download the freebie].

Build it as a simple website made of plain HTML, CSS and a little JavaScript, so I can host it anywhere.

Rules for this project:
- Never invent testimonials, numbers, results or guarantees. If something is missing, put a clearly marked placeholder and tell me.
- Write in plain, friendly language, the way I would say it to one person.
- Keep to one goal. There should be one main button, repeated where it makes sense.

Ask me anything you need before you start.

Claude will come back with questions. Expect things like who your ideal visitor is, what they worry about, whether you have a booking link yet, and which parts of your offer matter most. Answer in short, honest sentences. If you do not know, say so.

Why this matters

The questions are where your page gets its quality. Two minutes of real answers saves an hour of fixes later.

05

Step 5 of 10

Show Claude a page you love

A reference page tells Claude your taste faster than a paragraph of adjectives. Take a screenshot of a page whose look you admire, save it into your references folder, and say what you like about it.

If you want Claude to look at it, mention the file by name in your message, or type @ and the file name in the prompt box.

Be specific about what you are borrowing. Pick one or two of these:

  • Colours: "I like the warm cream background with the dark green buttons."
  • Layout: "I like that the headline sits next to the photo instead of above it."
  • Feel: "It feels calm and spacious. I want mine to feel like that, not busy."
  • Details: "I like how the testimonials sit in cards with the person's photo."

Tell Claude to take inspiration, not to copy. Add this line:

Prompt
Use this for the look and feel only. Do not copy its words, images or branding. Everything on my page should be mine.
No reference yet?

Skip this step. Describe the feel you want in three words and Claude will propose a direction in the plan.

06

Step 6 of 10

Get the plan before the build

Ask for the section plan first, because moving a heading in a plan costs seconds and moving it in a finished page costs a rebuild. After you have answered Claude's questions, send this:

Prompt
Show me the sections you would put on this page, in order. For each one, give me a one-line headline and say what it is there to do. Do not build anything yet.

If you are on the desktop app, switch the permission mode to Plan for this message. Claude then proposes without editing any files.

A page that gets people to book a call usually follows this order. Use it as a yardstick when you read Claude's plan.

OrderSectionIts job
1HeroSay who it is for and what they get, with one button and your photo
2The problemShow them you understand what they are dealing with
3The way outExplain your approach in a few plain sentences
4What happens on the callTake away the fear of the unknown
5ProofTestimonials, results, logos
6Who it is for and not forHelp the right people say yes and the wrong ones leave
7About youWhy you, in a few warm lines
8QuestionsAnswer the worries that stop people booking
9Final buttonRepeat the one action with a short reason to do it now

Read the plan like a visitor would. Does each section earn its place? Is anything there because pages "usually have it"? Cut it. Then make it yours:

  • Paste in your testimonials if they are not in the folder yet.
  • Answer any open questions Claude left.
  • Say "remove section 4" or "move proof above the problem" in plain words.
  • When you are happy, say: "Plan approved. Build it."
07

Step 7 of 10

Build it and open the preview

Switch the permission mode back to Manual or Accept edits, then send the build message. Claude writes the files and shows you the page.

Prompt
Build it and open a preview for me.

On the desktop app, Claude can run the page inside the app's Browser pane, where you can see it and where Claude can look at it too. You can also click the HTML file name in the chat to open it in that pane, or use the Preview dropdown in the session toolbar.

Your first look will be a decent draft, not a finished page. That is normal. The next step is where it becomes yours.

On the web app, Claude saves the finished files to your repository. To look at the page, ask: "How can I see this page right now? Give me the simplest way." The usual answers are downloading the files and opening index.html, or deploying a preview through your host, which Step 10 covers.

08

Step 8 of 10

Change things in plain language

Talk to Claude the way you would brief a designer sitting next to you. Name the part of the page, say what is wrong, and say what you want instead.

Layout and size

  • Make this heading bigger.
  • Shorten this section. Keep only the three strongest points.
  • Put the photo on the right and the text on the left.
  • There is too much space between the proof section and the FAQ. Tighten it.

Look and feel

  • Use my brand colours from colours-and-fonts.md for every button.
  • Make the whole page feel calmer. Fewer colours, more white space.
  • The button needs to stand out more. Make it the strongest thing on the screen.

Images

  • Use me-smiling.jpg in the hero, cropped so my face is not cut off.
  • Replace the stock-looking image in section 3 with my photo.
  • Add my logo to the top left and make it a link back to the top of the page.

Words

  • Rewrite the headline. It should speak to [who] and promise [result], in under 12 words.
  • This sounds too salesy. Write it the way I would say it on a call.
  • Cut every sentence that does not help someone decide to book.

Three habits make this go faster

  1. Point at things. "The heading that starts with 'You are not behind'" is clearer than "the second heading".
  2. Show, don't describe. Paste a screenshot of the problem and circle it if you can.
  3. Save versions. Before a big change, say: "Save a copy of the current page as a backup first." If you hate the result, say "go back to the backup".

You can also stop Claude mid-way. Click the stop button, or type a correction and press Enter. You do not have to wait for it to finish.

09

Step 9 of 10

Test it like a visitor

A page that looks great and sends the booking button nowhere is worse than no page. Spend ten minutes testing before you put it online. Start by asking Claude to check what it can check:

Prompt
Check this page at phone width and tablet width. Fix anything that overlaps, gets cut off, or is hard to tap with a thumb. Then go through every button and link and tell me exactly where each one goes.

Claude can confirm where a button points. It cannot tell you that a form submission reached your inbox or your CRM, and it cannot sit on your phone. Those two checks are yours.

About forms

A simple page has nowhere to store what people type. If you want a form, use one from a tool you already have (a form builder, your email platform, your CRM) and give Claude its embed code or link. Say: "Add this form embed under the final button section." That way details land where you already look.

Checklist before you publish

  • Opened the page on your own phone and scrolled the whole thing
  • Tapped every button and link
  • The booking button opens your calendar, and you completed a test booking
  • If there is a form, you submitted it with your own email and the details arrived where you expected
  • Read the page out loud once and fixed anything that does not sound like you
  • Every claim on the page is one you can back up
  • Images load fast and none look blurry or stretched
  • Footer has your correct contact details and a privacy link if you collect details

Then ask Claude to add the finishing touches that make a link look good when shared:

Prompt
Add a page title, a short description, and a share image so the link looks good when I paste it into LinkedIn, Instagram and WhatsApp. Add a favicon from my logo. Add alt text to every image.

Step 10 of 10

Put it online with your own address

Publishing means two things: putting the files on a host, then pointing your web address at that host. Claude cannot log into your accounts for you, so you do the clicking and Claude tells you what to click. Start with this message:

Prompt
I want to put this page online at my own domain, which is [yourdomain.com] (or: I have not bought a domain yet). I plan to use [Netlify / Cloudflare Pages / Vercel / GitHub Pages] (or: pick the easiest option for me). Walk me through it one step at a time. After each step, wait for me to tell you what I see before you move on.

Choose a host

All four of these can host a simple page, and each has a free plan at the time of writing. Check current limits on their sites.

HostHow the page gets thereGood if
NetlifyDrag and drop the folder, or connect GitHubYou want the quickest first launch
Cloudflare PagesDirect upload, or connect GitHubYou also want to buy your domain in the same place
VercelConnect GitHubYour files already live in GitHub
GitHub PagesTurn it on inside your repositoryYou are using the web app already

Host screens change often. If what you see does not match what Claude says, tell Claude what is on your screen, or paste a screenshot.

Connect your domain

  1. Buy the domain from a registrar such as Namecheap, Cloudflare or Porkbun. A common ending like .com usually costs somewhere around 10 to 20 dollars a year. That is an approximate range, so check the price at checkout.
  2. Add the domain in your host. Look for a setting called Domains or Custom domain.
  3. Copy the records your host shows you. They are called DNS records. Paste them into the DNS settings of the place where you bought the domain. Claude can tell you which fields go where if you share a screenshot.
  4. Wait. It can start working in minutes. Sometimes it takes a few hours, and occasionally up to two days.
  5. Check the padlock. Your host should set up the secure connection (https) on its own once the domain connects.
  6. Test both versions. Open yourdomain.com and www.yourdomain.com. Both should reach your page.
  7. Test the live page. Tap the booking button from your phone on the real address, not the preview.
Start on the free address

You can publish on the free web address your host gives you first, and connect your own domain later. Launching on the free address is a fine way to catch mistakes before your name is on it.

After launch

Learn from what happens

The page is live, so now you learn from it. Track one chain of numbers: visitors, button clicks, bookings. Ask Claude to add simple tracking:

Prompt
Add [Google Analytics / Plausible / Meta Pixel] to the page using this ID: [paste your ID]. Also track clicks on the main button as an event. Tell me where I will see the numbers.

Give it a couple of weeks of real visitors before you judge. These are rules of thumb, not laws:

What you seeLikely causeWhat to ask Claude
Few visitorsThe page is fine, the traffic is the issueNothing to change on the page yet. Work on where the link is shared
Visitors, but few button clicksThe top of the page is not landing"Give me five new headline options for the hero, each speaking to a different worry"
Clicks, but few bookingsFriction after the click"Look at the booking step from a visitor's side and list what might put them off"
Bookings, but wrong peopleThe page attracts the wrong audience"Tighten the who-it-is-for and not-for section"

Two habits keep the page easy to maintain

  • Make Claude remember your rules. Ask:
  • Update without starting over. Open the same folder in the Code tab, describe the change, and publish again. If your host is connected to GitHub, it updates itself. If you used drag and drop, drop the folder again.
Prompt
Create a CLAUDE.md file that records my brand colours, my voice rules, the one goal of this page and how it is built, so any future session follows them.

When you have a second offer, copy the folder, replace offer.md and testimonials.md, and ask Claude to adapt the page. Your brand work carries over.

Troubleshooting

If something goes wrong

Most problems have a one-line fix. Find your symptom and send Claude the words in the second column.

What is going wrongWhat to say
The page looks generic"Rewrite the headline and sections using only language from offer.md. Remove anything that could sit on any business's page."
The preview is blank"The preview shows a blank page. Find out why and fix it."
Claude changed something I did not ask for"Undo your last change and go back to the backup."
Colours or fonts are off"Match my brand exactly. The colours are [hex codes]. Use them for every heading, button and background."
The page is slow or images look huge"Resize and compress every image so the page loads fast. Keep the hero photo sharp."
It looks wrong on my phone"On a phone-sized screen, [describe what you see]. Fix it."
Claude keeps adding things I did not ask for"Only do what I ask. Do not add sections, features or text on your own."
The booking button opens the wrong page"Change every booking button to go to [paste your link] and open it in a new tab."
Claude invented a claim"Remove that claim. Only use facts from my files, and mark anything missing as a placeholder."

If the app itself is the problem

  • No Code tab, or a prompt to upgrade: Claude Code needs a paid plan. Check your plan, then sign in again and restart the app.
  • No environment selector under the prompt box: update the desktop app. Older layouts look different.
  • Cannot pick a folder on the web: the web app works from GitHub repositories, not from folders on your computer. Use the desktop app or upload your files to a repository.
  • A long session gets sluggish: start a new session in the same folder and tell Claude what you are working on. Your files stay exactly as they are.
